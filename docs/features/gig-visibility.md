# 공연 공개 범위 명세

> 작성일자: 2026-09-26
> 상태: 승인 회원 기준 수정 및 공유 운영 DB 정책 적용 완료 (2026-09-27), 앱 코드 배포 필요

## 1. 목적
공연의 공개 범위를 `비공개 | 회원 공개 | 전체 공개`로 구분합니다. 회원 공개는 관리자 승인이 완료된 회원에게만 허용합니다. 소셜 로그인과 가입 신청만으로는 회원 권한을 부여하지 않습니다.

## 2. 공개 범위와 권한

| 값 | 화면 표시 | 방문자·미신청·승인 대기·반려 계정 | 승인 완료 회원·공연 참여자 | 관리자 |
| --- | --- | --- | --- | --- |
| `private` | 비공개 | 조회 불가 | 조회 불가 | 조회 가능 |
| `members` | 회원 공개 | 조회 불가 | 조회 가능 | 조회 가능 |
| `public` | 전체 공개 | 조회 가능 | 조회 가능 | 조회 가능 |

- 목록, 상세, 페이지 메타데이터에서 요청 단위로 캐시한 `getGigViewer()`와 동일한 `canViewGig()` 규칙을 적용합니다. 회원 여부는 검증된 로그인 계정의 `users.status = 'approved'`로 판단하며, 프로필 조회 실패·프로필 누락은 미승인으로 처리합니다. 승인 후 선택 항목인 세션을 비워도 회원 권한은 유지합니다. 비공개 공연은 참여자로 배정되어 있어도 관리자만 조회합니다.
- 권한이 없으면 공연명·장소·셋리스트·출연자 등 내용을 제공하지 않습니다. 로그인 전에는 로그인 안내를 제공하고, 미승인 계정에는 가입 승인 완료가 필요하다고 안내합니다.
- 생성·수정은 관리자 전용입니다. 새 공연의 기본 공개 범위는 기존 동작과 동일한 **회원 공개**입니다.
- 회원 공개/전체 공개 공연에는 승인 완료 회원과 관리자가 참가 신청할 수 있습니다. 실제 공연자는 기존대로 재신청할 수 없습니다. 비공개 공연에는 관리자가 아닌 회원의 신청을 차단합니다.
- 선곡회의는 공연을 조회할 수 있는 사용자 중 해당 공연 참여자와 관리자만 이용하며, 후보곡 마감 및 수정 권한 규칙을 유지합니다.

## 3. 데이터 모델 및 전환

- `gigs.visibility`: `text NOT NULL DEFAULT 'members'`, CHECK 값은 `private`, `members`, `public`.
- 기존 `is_public=false`는 `members`, `true`는 `public`으로 일괄 전환합니다. 기존 공연을 새 관리자 전용 비공개로 자동 변경하지 않습니다.
- `is_public`은 호환용으로 유지하며 트리거가 `visibility='public'` 여부로 동기화합니다. 신규 저장·권한 판단은 `visibility`를 기준으로 합니다.
- 마이그레이션 전 행을 읽을 때는 `getGigVisibility()`가 기존 boolean 값을 해석합니다. 잘못된 명시적 공개 범위는 비공개로 취급합니다.
- `gigs` SELECT RLS는 위 권한표를 적용하며, 기존 허용형 정책의 우회를 막는 제한형 정책도 추가합니다. 공연자·확정 셋리스트·후보곡·후보곡 응답의 SELECT에도 상위 공연의 조회 권한을 적용합니다.
- 배포 전 [20260926083828_add_gig_visibility_levels.sql](../../supabase/migrations/20260926083828_add_gig_visibility_levels.sql)을 적용해야 합니다. 기존 마이그레이션 순서를 유지하고 적용 후 `npm run types`를 실행합니다.
- 2026-09-26 사용자 승인 후 운영 DB에 적용하고 `npm run types`를 성공적으로 실행했습니다. 공개 범위 타입은 기존 수동 정의와 일치합니다. 별도 미적용 마이그레이션의 `users.marketing_opted_in_at` 타입은 기존 로컬 기능과의 호환을 위해 보존했습니다.

## 4. 서버 액션

- `createGig`, `updateGig`: 필수 FormData `visibility`를 세 값 중 하나로 검증하고 저장합니다. 누락·잘못된 값 또는 비관리자 요청은 DB 변경 전에 거절합니다.
- `submitGigRsvp`: 승인 완료 회원·관리자 여부를 먼저 확인한 뒤, 회원 공개/전체 공개 공연의 신청을 허용합니다. 비공개는 관리자만 허용합니다. 미승인 계정은 전체 공개 공연에서도 신청할 수 없습니다.
- 공개 범위 수정 후 목록·상세·선곡회의 관련 캐시를 갱신합니다.

## 5. 화면

## 7. 운영 적용 확인 (2026-09-26)

- 사용자 승인 후 `add_gig_visibility_levels` 마이그레이션을 적용했습니다. 실제 DB 이력 `20260926083828`에 맞춰 로컬 SQL 파일명도 동기화했습니다.
