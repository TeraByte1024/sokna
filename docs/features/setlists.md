# 셋리스트 및 선곡 관리 명세 (Setlists & Nominations)

## 1. 기능 개요
특정 공연(`gig_id`)에 참여하는 멤버들이 연주할 후보곡을 등록(`nominations`)하고, 곡별 필요 세션(보컬, 기타, 베이스, 드럼, 건반 등), 악보 보유 여부, 참고 링크(유튜브, 음원 등), 상세 설명을 공유하고 협업하는 기능입니다. 선곡 회의가 완료된 후 실제 공연에 오를 확정 곡 목록은 `setlists` 테이블로 분리 관리되며, 공연 수정 화면에서 선곡회의 후보곡을 쉽게 텍스트 복사하여 셋리스트로 일괄 추가할 수 있습니다.

---

## 2. 세부 명세

### 2.1 선곡회의 후보곡 목록 및 상세 패널 (`/gigs/[id]/nominations`)
- **접근 권한 (보안 검사)**:
  - **화면 접근 권한**: 오직 **해당 공연의 참여 세션원(`performers`) 및 관리자(`is_admin()`)**만 접근 가능.
  - 비로그인 사용자는 로그인 페이지로 자동 리다이렉트되며, 비참여 부원은 "공연 참여자 전용 화면" 안내 뷰를 표시하여 정보 노출을 차단합니다.
- **조회 조건**:
  - `getNominationGigRow()`로 메타데이터·본문의 공연 정보 조회를 요청 단위로 공유하고, `getAuthUser()`로 본문·관리자 판정의 `auth.getUser()` 검증을 공유합니다. 공연 조회와 인증을 병렬 실행하고 인증 후 관리자·참여자 판정도 병렬 실행합니다. 접근 허용 후 후보곡·전체 공연자·마지막 조회 시점을 병렬 조회하며, 곡 상세와 응답에 필요한 기존 데이터는 그대로 전달합니다. 계정 간·요청 간 데이터를 캐시하지 않습니다.
  - `nominations` 테이블에서 `gig_id == [id]`에 해당하는 모든 후보곡을 **항상 등록순(처음 등록한 것이 위로 오도록 오름차순)**으로 조회 및 정렬 표시.
  - 곡 등록자(`created_by` -> `performers` -> `users`) 정보를 조인하여 기수, 파트, 작성자 이름 표시. 기수 정보가 확인되지 않거나 미연동된 공연자(스프레드시트 등록 등)의 경우 0기 대신 **이름만 단독 표시**하며, 공연 참여자 정보 조회 시 `user_id` 미연동 상태라도 사용자 프로필 이름 기반으로 fallback 매칭 지원.
- **등록·수정 후 화면 이동**: 곡과 인앱 알림이 기존 DB 트리거를 통해 저장되면 캐시를 갱신하고 성공 응답을 반환하며, 폼은 선곡회의 목록으로 이동합니다. FCM은 서버의 Next.js `after` 콜백에서 응답 이후 처리하므로 사용자가 발송 완료를 기다리지 않습니다. 작업 등록·발송 실패는 저장 성공을 바꾸지 않고 기존 outbox·cron 복구를 사용합니다. DB 구조와 트리거는 변경하지 않습니다.
- **주요 UI 요소**:
  - `NominationPanel`: 서버가 전달한 첫 조회 결과를 즉시 표시합니다. 상단은 기존 안쪽 여백과 둥근 카드를 유지하면서 은은한 primary 색조 배경·테두리와 부드러운 그림자로 후보곡 카드보다 살짝 강조하며 `{공연 제목} 선곡회의`를 단일 제목으로 표시하고 긴 공연 제목만 말줄임표로 줄여 `선곡회의`와 상단 경로의 나머지 문구는 유지. 별도 부제목과 내 참여 세션·D-Day·공연일·공연 장소는 숨기고 데스크톱에서 정보 영역의 `선곡회의` 레이블 없이 달력 아이콘·날짜와 위치 아이콘·장소를 구분선 사이에 두고 한 행에 나란히 표시하며, 오른쪽 정렬한 시계 아이콘·추천 마감 문구·남은 기간도 날짜와 장소 옆 같은 행에 한 줄로 표시하며 긴 장소명은 말줄임표로 줄임. 모바일에서는 `선곡회의` 정보 레이블 없이 크기와 시작 위치를 맞춘 달력·위치·시계 아이콘 뒤에 각각 데스크톱과 동일한 전체 날짜(`2026년 10월 9일 금요일`), 회의 장소, 한 줄짜리 추천 마감 기한을 순서대로 한 행씩 표시하고, 장소 아이콘과 텍스트는 같은 높이로 맞춰 긴 장소명은 텍스트 시작 위치에서 줄바꿈. 큰 화면에서는 날짜 옆에 회의 장소를 표시하고, 날짜나 장소가 없거나 공백이면 각각 `날짜 미정`, `장소 미정`을 아이콘 뒤에 표시하고 장소 텍스트는 기본 글자색을 사용. 데스크톱의 `곡 추천하기` 버튼은 추천 마감 정보 행의 하단에 정렬. 마감 레이블은 `추천 마감까지`로 표시하고 남은 기간과 글자 크기를 맞춤. 마감 카운트다운은 남은 일·시간·분 중 가장 큰 단위만 보여주며 `남았어요`는 보통 굵기로 표시하고, 마감 후에도 제목 위의 별도 `추천 마감` 칩 없이 모바일·데스크톱 정보 행에 `추천곡 접수가 마감되었습니다`만 표시. 실시간 검색 및 3대 확장 필터(세션, 응답, 악보) 토글 바, 곡 카드 그리드(항상 등록순 정렬)를 제공. 모바일에서는 후보곡 추천 액션을 우측 하단의 원형 `+` 플로팅 버튼으로 제공하고 상단 카드에서 숨겨진 데스크톱 버튼 영역의 빈 공간은 없애며, 데스크톱에서는 기존 텍스트 버튼을 표시.
  - `PartChip`: 필요 악기 세션 파트 뱃지 (flat 스타일, `보컬(남)`/`보컬(여)` 표준화, **보컬 -> 코러스 -> 기타 -> 베이스 -> 드럼 -> 건반 -> 이외** 일관된 순서로 자동 정렬). 모든 화면 크기에서 곡 카드 정보 영역은 **`곡 제목 - 아티스트 | 상세보기` → `필요 세션·악보 | 나의 응답` → `어필 | 작성자`**의 3행 위치 구조로 통일하되, `상세보기`는 기존처럼 데스크톱 hover 시에만 노출하고 작성자는 기존 중립 칩 스타일을 유지. 전체 가능/불가능 인원 집계는 노출하지 않고, 공연 참가자인 경우에만 사용자의 응답을 세션별 아이콘 칩(`✓ 베이스`, `× 코러스`, `? 기타` 등)으로 표시. 악보 칩은 필요 세션 끝에 배치하며 모바일에서는 `악보 O`/`악보 X`, `sm` 이상에서는 `악보 있음`/`악보 없음`으로 표시. 썸네일은 **유튜브 표준 16:9 비율(`aspect-video`, 데스크톱 `sm:w-36 aspect-video`)**을 적용.
  - `NominationDrawer`: 처음 곡을 열 때 코드를 지연 로드합니다. 곡 기본 정보(타이틀, 아티스트, 추천자, 등록/수정 일시) -> **영상**(YouTube 동영상 임베드, 탭, 구간 우선 타임스탬프 퀵 칩, Full 설명) -> **어필**(작성자 설명) -> **악보**(악보 보유 상태 뱃지) -> **세션**(일관 정렬, **첫 번째 세션을 기본 선택하고 세션 버튼 클릭 시 해당 세션 참여자의 인라인 응답 현황 표시**) -> **나의 응답**(내 응답 상태 뱃지 및 가능 여부 응답 모달 버튼) 순서로 최적화 배치. 모바일 디자인을 모든 화면 크기에 적용하여 `가능 여부 응답` 버튼을 드로어 하단에 고정하고 본문 하단 여백을 유지. 모바일(640px 미만)은 최대 너비 제한과 왼쪽 테두리·바깥 그림자 없이 화면 좌우를 완전히 채우는 불투명 drawer로 표시하고, 640px 이상은 기존 우측 최대 너비를 유지. 미디어 탭 너비·세션 글자 크기·응답 현황 세로 배치와 추천 보컬 `추천` 텍스트 배지도 화면 크기와 무관하게 동일. (기존 드로어 내 '추천 보컬' 섹션은 제거되고, 세션 참여자 인라인 응답 현황 내 해당 보컬에게 '추천 보컬' 뱃지로 통합 표시). 서랍 열림 시 **배경(body) 스크롤 고정(`overflow: hidden` 및 스크롤바 너비 보정)** 및 `overscroll-contain`, ESC 키 닫기를 적용하여 이중 스크롤바 및 배경 스크롤 누수를 방지. 권한자(직접 등록한 부원/관리자)에게 헤더 [수정] 버튼 제공 (클릭 시 `/gigs/[id]/nominations/[songId]/edit` 전용 페이지로 이동).
  - `NominationForm` (후보곡 등록/수정 전용 페이지 폼): 인풋 필드에서 Enter 입력 시 실수로 폼이 제출되지 않도록 방지, 곡 기본 정보, **악보 상태 세그먼트(`악보`: `악보 있어요` / `악보 없어요`) 및 악보 메모(`sheetNote`, 넉넉한 폭과 내용 초과 시 멀티라인 지원 Textarea)** 필드, **`필요 세션`**(신규 등록 시 기본값: **기타 1, 베이스 1, 드럼 1**, 추가 칩 및 고정 정렬: 보컬 > 코러스 > 기타 > 베이스 > 드럼 > 건반 > 이외), 세션 안내 텍스트 및 모바일 툴팁(`CircleHelp`), 선택된 세션 우측 상단 `총 n명` 카운트, `+ 직접 입력` 인라인 텍스트 필드, **`추천 보컬`**(컴팩트 칩 및 `+ 추가` 버튼 클릭 시 검색 인풋 전환 & 플로팅 드롭다운 팝업), **참고 링크**(유튜브 영상 레이아웃 순서: **1. 링크 URL → 2. 영상 미리보기 → 3. 타임스탬프 독립 목록/추가 → 4. 순수 설명 에디터**, **`[⏱️ 현재 시점 설명 추가]` 실시간 IFrame 재생 시간 캡처 및 일시정지**, 비유튜브 링크는 타임스탬프 숨김), 어필 작성/수정, 작성 중 이탈 방지 경고 팝업. 제목·아티스트뿐 아니라 악보, 필요 세션, 추천 보컬, 링크/타임스탬프 등 폼 전체 변경을 감지하며 상단 로고를 포함한 내부 링크 클릭도 확인 다이얼로그를 거침. (수정 페이지 하단 좌측에 `[🗑️ 추천곡 삭제하기]` 배치).

### 2.2 곡 등록 및 수정 (`NominationForm`, `addSetlist`, `updateSetlist`)
- **등록 및 수정 페이지 라우트**:
  - 신규 등록: `/gigs/[id]/nominations/new`
  - 정보 수정: `/gigs/[id]/nominations/[songId]/edit`
- **등록 자격 (보안 검사)**:
  - 로그인된 유저가 해당 공연(`gig_id`)의 `performers` 테이블에 등록되어 있어야 함 (`user_id` & `gig_id`) 또는 관리자 권한(`is_admin()`).
  - 일반 참여자는 공연별 `nomination_deadline`이 설정된 경우 그 시각 전까지만 등록할 수 있습니다. 마감 기한이 없으면 계속 등록할 수 있으며, **관리자(Admin)는 마감 이후에도 상시 등록 가능**.
  - 마감 시각은 공통 유틸리티(`lib/nomination-deadline.ts`)로 판정합니다. 마감 시각과 같거나 이후이면 일반 참여자의 등록을 차단합니다. 값이 없으면 선곡회의 날짜와 관계없이 마감하지 않습니다.
  - 마감 시각이 없으면 선곡회의 상단에 추천 마감 정보(카운트다운·마감 안내)를 표시하지 않으며, 참여자의 추천곡 등록은 계속 허용합니다.
  - 마감 후 추천 버튼은 링크가 없는 실제 `disabled` 버튼으로 표시하여 클릭 및 키보드 이동을 차단. 등록 URL 직접 접근 시 서버에서 선곡회의 목록으로 리다이렉트.
  - `addNomination` 및 호환 액션 `addSetlist`는 저장 직전에 공연의 최신 `nomination_deadline`과 서버 시각으로 마감을 재검사합니다. 마감 전에 열어 둔 폼을 제출해도 마감 후면 오류를 반환하며 후보곡과 알림 큐를 생성하지 않습니다.
  - 참여자나 관리자가 아닐 경우 `"이 공연의 참여자로 등록되지 않았습니다."` 에러 반환.
- **수정 자격 (보안 검사)**:
  - 후보곡 작성자 본인(`created_by`) 또는 관리자(`is_admin()`)만 수정 및 삭제 가능. 비인가 사용자 접근 시 차단 카드 렌더링.
- **입력 데이터 구조**:
  ```ts
  export interface SetlistFormValues {
    title: string;          // 곡 제목
    artist: string;         // 아티스트명
    requiredParts: string[]; // 필요 세션 배열 (예: ['보컬(남)', '기타', '드럼'])
    recommendedVocals: {    // 추천 보컬 목록 (jsonb)
      id: number;           // performer id
      name: string;
      generation?: number | null;
      part?: string;
    }[];
    sheetExists: boolean;   // 악보 보유 여부
    sheetNote?: string;     // 악보 관련 추가 메모 (키 정보, 보유 파트, 링크 등)
    description: string;    // 메모 및 특이사항 (기본 높이 5줄 이상)
    links: {                // 참고 URL 목록 (jsonb)
      url: string;
      note?: string;        // 순수 링크 설명 (기본 높이 5줄 이상)
      timestamp?: string;   // 호환용 시작 시각
      timestamps?: {        // 독립 타임스탬프 목록
        id?: string;
        time: string;       // 포맷: '1:23', '0:45', '1:23 ~ 2:45' (선행 0 strip)
        label: string;      // 구간 설명 (미입력 시 빈 문자열로 저장되며 UI에서 단독 표시)
      }[];
    }[];
  }
  ```
- **후보곡 폼 섹션 배치 순서**:
  - `1. 곡 기본 정보` (제목, 아티스트, 악보 보유 여부 및 메모)
  - `2. 필요 세션` (세션별 필요 인원 및 추천 보컬 선택)
  - `3. 어필 및 제안 메모` (추천 이유, 편곡 방향, 키 조절 등)
  - `4. 참고 링크` (유튜브 영상 링크, 미리보기, 타임스탬프, 설명)
- **수정 페이지 및 입력 UX 규칙**:
  - **직접 입력 세션 추가**: 후보곡 작성·수정 폼의 직접 입력 필드는 Enter뿐 아니라 포커스가 빠지는 `blur` 시에도 현재 입력값을 기존 세션 추가 로직으로 처리합니다. 앞뒤 공백을 제거하고 빈 값은 추가하지 않으며, 추가 후 입력값을 초기화하여 Enter 후 blur로 같은 입력이 재추가되지 않게 합니다.
  - **타임스탬프 구간+설명 동시 입력 자동 파싱**: `TimestampBuilder`에서 `01:23 기타 솔로`, `02:5~02:15 기쏠`, `1:20 ~ 2:10 브릿지`와 같이 시간(초 단위 1자리 `02:5`도 `2:05`로 자동 보정)과 설명을 한 번에 입력하면 정규식을 통해 시간(선행 0 제거)과 설명을 자동으로 분리 파싱하며, 별도 2단계 확인 없이 엔터 한 번으로 즉시 타임스탬프가 추가됩니다.
  - **빠른 라벨 프리셋 제거**: 번거로운 고정 프리셋 버튼(+인트로, +벌스 등)을 제거하여 인터페이스를 단순화하고 사용자의 자유로운 직접 입력을 극대화.
  - **추천 보컬 선택기 키보드 지원 및 간소화**: 드롭다운 상단의 불필요한 헤더(`공연 참여자 목록 | n명`)를 제거하고, 위/아래 방향키(`↑`, `↓`)로 참여자 항목 포커스 이동 및 `Enter` 키로 즉시 선택/토글할 수 있도록 키보드 네비게이션을 전면 지원.
  - **영상 미리보기 즉시 렌더링**: 수정 페이지 진입 시 등록된 YouTube 영상을 대기/지연 없이 즉시 렌더링하며, 불필요한 자동재생(`autoplay=1`)으로 인한 브라우저 차단/정지 현상을 방지. 타임스탬프 칩 클릭 시에만 `postMessage` 기반으로 부드럽게 점프 및 재생.
  - **타임스탬프 시간 표기 0 strip**: `01:23` -> `1:23`, `00:45` -> `0:45`, `00:00` -> `0:00`, `01:23 ~ 02:45` -> `1:23 ~ 2:45`와 같이 분/시간 단위 선행 0을 제거하여 간결하고 읽기 쉽게 표시.
  - **타임스탬프 버튼 줄바꿈(Wrap) 및 전체 표시**: 타임스탬프 설명이 길어지거나 여러 개가 등록되더라도 말줄임표(`truncate`)로 잘리지 않고, `flex-wrap` 및 `break-words`를 통해 block 단위로 자연스럽게 줄바꿈되어 모든 타임스탬프와 설명 내용이 온전히 표시됩니다. (등록 폼 및 상세 드로어 공통 적용)
  - **타임스탬프 단독 표기**: 설명이 없거나 '주요 구간', '지정 구간' 등의 기본 플레이스홀더인 경우 라벨을 강제로 노출하지 않고 `[▶ 1:23]` 타임스탬프만 단독 표시.
- **참고 링크 설명 표시**: 유튜브 영상 아래 설명과 일반 외부 링크 카드 설명 모두 입력한 줄바꿈을 보존하고 말줄임표나 줄 수 제한 없이 전체 내용을 표시합니다. 타임스탬프 클릭 동작은 유지하며 긴 텍스트는 영역 폭에 맞춰 줄바꿈합니다.
- **데이터베이스 반영**:
  - `nominations` 테이블에 insert / update.
  - `created_by` 컬럼에는 유저의 `performers.id`가 저장됨.
  - `sheet_note` 컬럼에 악보 메모 저장.
  - `recommended_vocals` 컬럼(jsonb)에 추천 보컬 목록 저장.
  - 등록 및 수정 완료 후 `revalidatePath('/gigs/${gigId}/nominations')`로 갱신.

### 2.4 [선곡회의 곡 가져오기] 다이얼로그 (`NominationImportDialog`)
- **목적**: 선곡 회의에서 제안된 곡 중 실제 공연에 오를 곡들을 공연 관리자가 손쉽게 선택하여 공연 셋리스트(`setlists`)로 텍스트 복사 추가.
- **접근 경로**: 공연 정보 수정 페이지(`/gigs/:id/edit`)의 SETLIST 관리 헤더의 `[선곡회의 곡 가져오기]` 버튼.
- **동작 흐름**:
  1. 버튼 클릭 시 해당 공연의 `nominations` 목록을 불러오는 모달 표시.
  2. 실시간 검색(곡 제목, 아티스트, 추천인, 세션) 및 다중 선택 체크박스(전체 선택/해제 지원) 제공.
  3. 세션 뱃지는 표준화된 순서(보컬 -> 기타 -> 베이스 -> 드럼 -> 건반 -> 이외)로 정렬 표시되며, 추천 보컬 정보도 함께 제공.
  4. [선택한 N곡 추가하기] 클릭 시, 선택된 곡의 제목, 아티스트 및 기본 세션 슬롯(추천 보컬 자동 배정 포함) 정보를 셋리스트 행으로 자동 추가.
  5. 기존 스프레드시트 붙여넣기 기능(`SetlistBulkImporter`)과 완벽히 병행하여 사용 가능.

### 2.5 후보곡별 세션 참여 가능 여부 및 메모 (`nomination_responses`)
- **추천 보컬 응답 대상 연결**: 추천 보컬 JSON의 `userId` 또는 현재 공연자의 `id`로 지목 여부를 판단합니다. 계정 ID가 없는 기존 추천 보컬도 공연자 ID로 연결하여 상세 응답과 수정 알림의 대상 판정을 통일합니다.
- **수정 알림**: 수정 후에도 이미 응답한 세션이 남아 있으며 해당 세션의 응답 대상인 현재 공연 참여자에게만 알림을 생성합니다. 없어진 세션의 과거 응답만 있거나 응답 대상에서 제외되면 수신하지 않습니다. 수정자를 제외하고 계정당 한 번 생성합니다. [후보곡 수정 알림](./nomination-update-notifications.md) 마이그레이션은 2026-10-08 연결된 DB에 적용했습니다.
- **응답 이후 원문 수정**: 저장된 나의 세션 응답보다 곡 수정 시각이 늦으면 목록에 `응답 후 수정됨`, 상세에 `마지막 응답 이후 글이 수정되었습니다`를 표시합니다. 열람으로 해제되지 않고 응답 재저장 성공 시 해제되며, 동일 내용의 곡 저장은 수정으로 처리하지 않습니다. 자세한 규칙은 [응답 이후 후보곡 수정 안내](./nomination-response-review.md)를 따릅니다.
- **응답 토스트**: 가능 여부 저장 성공/실패는 하단 중앙에 표시하여 닫기 버튼을 가리지 않습니다. 모바일 토스트는 하단 고정 응답 버튼과 안전 영역 위로 간격을 둡니다.
- **목적**: 공연 참여 세션원들이 선곡회의 후보곡 각각에 대해 자신의 연주/보컬 참여 가능 여부를 표시하고, 곡에 대한 세션 조율 메모(예: 솔로 카피 필요, 키 조절 희망 등)를 남길 수 있도록 지원합니다.
- **가능 여부 상태 (3종)**:
  - `available` (가능 🟢)
  - `undecided` (미선택 ⚪, 기본값)
  - `unavailable` (불가능 🔴)
- **메모 (`comment`)**:
  - 선택 사항으로 텍스트 입력 가능.
  - 공연 참여 회원과 관리자 모두 응답 현황에서 메모 전체를 확인할 수 있으며, 다른 참여자의 메모와 `나의 응답` 메모는 말줄임표나 줄 수 제한 없이 입력한 줄바꿈을 보존합니다. 긴 텍스트는 카드 폭에 맞춰 자연스럽게 줄바꿈합니다. 악보 메모도 입력한 줄바꿈을 보존합니다.
  - 후보곡의 세션별로 상태 및 메모를 저장(`UNIQUE(nomination_id, user_id, session_part)`). 복수 세션을 부여받은 부원은 각 세션별로 독립적인 응답 가능.
  - **Local Custom 세션**: 곡 추천자가 추가한 세션 중 기본 세션(보컬, 기타, 베이스, 드럼, 건반 및 동의어)에 속하지 않고 공연 참여자에게 배정되지 않은 세션은 곡끼리 공유되지 않으며, 세션 배정과 무관하게 모든 공연 참여자가 자유롭게 응답 가능. 기본 세션은 배정자가 없어도 Local Custom으로 분류하지 않으며, 다른 세션 참여자를 응답 현황·충족 인원 집계·나의 응답 선택지에 포함하지 않음. 예: 기타 배정자가 없는 공연에서 건반 참여자를 기타 미응답자로 표시하지 않음.
- **UI 및 동작 흐름**:
  - **곡 상세 바로가기**: `/gigs/[id]/nominations?song=[곡 ID]`에 접근하면 해당 공연에서 조회된 곡의 상세 서랍을 즉시 연다. 잘못된 ID나 다른 공연의 곡은 열지 않으며 기존 인증·공개 범위 검증을 유지한다.
  1. **곡 상세 서랍(`NominationDrawer`) 내 세션 버튼 및 내 응답 섹션**:
     - **나의 응답 섹션 제목**: 단일·복수 세션 및 배정 세션이 없는 상태 모두 콜론 없는 `나의 응답` 제목과 메시지 아이콘을 카드 위에 표시합니다. 모든 화면 크기에서 응답 버튼을 하단 고정 위치에 표시합니다. 복수 세션은 제목에 세션 개수를 함께 표시합니다.
     - **나의 응답 세션 칩 디자인**: 단일·복수 세션의 표시 영역과 응답 입력 모달에서 세션 칩을 응답 현황 목록과 동일한 디자인(`text-[11px]`, `font-semibold`, `px-2 py-0.5`, `rounded-md`, `bg-muted/80`, `text-muted-foreground`, `border-border/60`)으로 표시합니다. 추천·자유 세션 표시는 유지합니다.
     - **응답 상태 칩 색상 유지**: 상세 화면의 `나의 응답`(단일·복수 세션)과 세션 응답 현황의 상태 칩은 `Badge`의 `outline` 변형을 사용합니다. 마우스를 올리거나 모바일에서 눌러도 가능(초록)·불가능(빨강)·미응답(중립)의 상태 색상을 유지하며 기본 primary hover 배경을 적용하지 않습니다.
     - **세션 뱃지 색상 통일**: `보컬(남)`과 `보컬(여)`의 남/여 구분 색상(파랑/빨강)을 제거하고, 다른 일반 세션 뱃지와 동일한 중립 카드 스타일로 통일.
     - **필요 세션 뱃지 클릭 시 인라인 세션 응답 현황**:
       - 첫 번째 세션 파트를 기본 선택하고, 필요 세션 뱃지를 클릭하면 해당 세션의 참여자 응답 상태(🟢 가능 / 🔴 불가능 / ⚪ 미응답)와 메모를 드로어 본문에서 확인합니다. 제목은 `{세션} 세션 응답 현황`으로 표시합니다.
       - 참여자가 많더라도 목록 높이 제한이나 목록 내부 스크롤 없이 선택된 세션의 모든 참여자 응답을 기본적으로 펼쳐 표시합니다. 긴 상세 내용은 드로어 본문의 공통 스크롤로 탐색합니다.
       - 상세 드로어의 인라인 응답 목록과 통계는 현재 공연의 세션 배정(`performers.part`)을 기준으로 구성하고, 해당 세션의 응답만 연결함. 과거 응답이 남아 있어도 다른 세션으로 배정되었거나 공연에서 제외된 사람을 목록에 추가하지 않으며, 표시 파트도 회원 프로필(`users.part`) 대신 공연 배정을 사용함. 추천 보컬과 Local Custom 세션의 참여 예외는 유지.
       - **추천 보컬 뱃지 통합 표시**: 해당 보컬 참여자 행에 별 아이콘 없는 `추천` 텍스트 뱃지를 모든 화면 크기에서 표시하며 정렬 우선순위(본인 다음 상단)를 부여합니다. 나의 응답·응답 입력 모달·세션 응답 대화상자의 추천 표기도 `추천` 텍스트로 통일합니다.
     - **곡 상세 섹션 제목 통일**: 어필·악보·세션·나의 응답 제목은 `text-xs font-black tracking-wider uppercase text-muted-foreground flex items-center gap-1.5`와 `size-3.5 text-primary` 아이콘으로 통일합니다. 악보 제목의 콜론을 없애고 상태 뱃지와 줄바꿈을 보존하는 메모는 제목 아래에 배치합니다.
     - **곡 상세 섹션 순서 최적화**:
       - 곡 감상 및 검토 흐름에 맞춰 **`영상 > 어필 > (악보 상태) 악보 > 세션 > 나의 응답`** 순으로 섹션을 재배치하여 부원들이 영상을 보고, 추천 어필을 읽은 뒤, 악보와 필요 세션을 확인하고 자신의 참여 가능 여부를 최종 등록할 수 있도록 최적의 UX를 제공.
  2. **후보곡 목록 카드(`SetlistCard`)**:
     - 세션 응답 상태 칩은 그림자 없이 표시합니다. 기본·간략 목록, 곡 상세의 참여자 응답과 나의 응답 상태 칩 모두 동일하게 적용합니다.
     - 목록 위의 **기본 / 간략** 버튼으로 표시 형식을 전환합니다. 기본값은 기존 카드이고, 간략 보기는 `곡 제목 - 아티스트 · 세션별 내 응답 칩 | 기수 작성자` 순서로 표시하며 칩을 작성자 구분선 바로 앞에 배치합니다. 두 보기 모두 `getEligibleSessionsForUser`로 구한 모든 응답 가능 세션을 공통 상태 칩의 `{아이콘} {세션명}`으로 표시합니다. 가능은 초록 체크, 불가능은 빨강 X, 미저장·미정은 회색 물음표입니다. 간략 보기의 작성자와 구분자는 화면 폭 768px 이상이면서 카드 폭 640px 이상인 경우에만 표시합니다. 검색·필터·등록순·상세 서랍 동작과 신규·수정 곡의 색상 강조를 유지하며 새로고침 시 기본값으로 돌아갑니다. [목록 표시 형식 명세](./nomination-list-display.md)를 따릅니다.
     - 전체 가능/불가능 인원 집계는 표시하지 않으며, 현재 사용자가 해당 공연의 참가자인 경우에만 세션별 내 응답 아이콘 칩을 표시합니다. 공연 참가자가 아닌 관리자는 내 응답 영역을 표시하지 않습니다.
     - 악보 여부는 필요 세션 칩 행의 마지막에 표시하며 모바일에서는 `악보 O`/`악보 X`, `sm` 이상에서는 `악보 있음`/`악보 없음` 레이블을 사용. 모바일과 데스크톱 모두 동일하게 `곡 제목 - 아티스트 | 상세보기`, `필요 세션 | 나의 응답`, `어필 | 작성자`의 3행 구조로 구성.
  3. **상단 필터 툴바**:
     - 목록 보기 버튼은 검색·필터 영역 다음 독립 행 오른쪽에 배치하며 `LayoutList`(기본) / `List`(간략) 아이콘을 사용합니다. 모바일은 아이콘만, `sm` 이상은 아이콘과 레이블을 함께 표시하고 접근성 이름·툴팁·선택 상태를 제공합니다.
     - 검색창과 필터 버튼은 별도 카드 없이 배치하고, 펼친 세션·응답·악보 필터 영역만 둥근 테두리·은은한 배경·안쪽 여백·약한 그림자의 박스로 묶습니다. 개별 입력창과 버튼의 테두리는 유지합니다.
     - 모바일과 데스크톱에서 세션·응답·악보 캡션의 콜론을 없애고 좁은 동일 폭으로 맞춰 버튼 그룹과 각각 같은 행에 두고, 세션 필터도 나머지 두 필터와 같은 둥근 테두리·연한 배경의 분할 버튼으로 표시합니다. 좁은 화면에서는 버튼 그룹 내부를 가로 스크롤하고 활성 필터 초기화 버튼은 별도 행 오른쪽에 둡니다.
     - 별도 [필터] 아이콘 버튼을 통해 확장/축소되는 3가지 필터 패널 제공:
       - **세션 필터**: `전체`, `보컬(남)`, `보컬(여)`, `건반` (기타, 베이스, 드럼 항목 제외)
       - **내 응답 필터**: `전체`, `가능`, `불가능`, `미선택`
       - **악보 필터**: `전체`, `악보 있음`, `악보 없음`
     - 필터 패널이 닫혀있을 때도 활성화된 필터 개수 뱃지 및 빠른 해제 칩을 노출하여 직관적으로 필터 상태 확인 및 초기화 가능.
     - 최신순/가나다순 정렬 토글 버튼을 제거하고, 항상 최초 등록순(과거 등록된 곡이 상단)으로 일관되게 정렬 표시.
