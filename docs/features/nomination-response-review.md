# 응답 이후 후보곡 수정 안내

> **작성일자**: 2026-10-07  
> **작성자**: Codex  
> **상태**: Completed

## 1. 배경 및 목적

가능 여부 응답 후 후보곡의 원문이 바뀌었을 때 재확인이 필요함을 표시한다. 읽음 기준의 신규/수정 하이라이트와 독립적으로 유지한다.

## 2. 세부 요구사항

- 현재 공연에서 응답 가능한 세션에 저장된 나의 응답이 있고, 곡의 수정 시각이 해당 응답 수정 시각보다 늦으면 재확인 대상으로 판단한다. 여러 세션 중 하나라도 해당하면 표시한다.
- 미응답, 동일한 시각, 잘못된 시각은 수정 이후 응답으로 판단하지 않는다.
- 곡을 열거나 모두 확인해도 안내를 해제하지 않는다. 응답 내용을 바꾸지 않아도 성공적으로 다시 저장하면 해제한다. 저장 실패 시 기존 상태와 안내를 유지한다.
- 제목, 아티스트, 필요 세션, 추천 보컬, 악보 여부/메모, 어필, 참고 링크/설명의 실제 변경만 곡 수정 시각을 갱신한다. 내용이 같은 저장은 수정으로 취급하지 않는다.

## 3. 데이터 모델

기존 테이블 유지. nominations.updated_at과 nomination_responses.updated_at을 사용하며 스키마를 변경하지 않는다.

## 4. Server Action

- 2026-10-08 추가: 수정 후에도 기존 응답 세션의 응답 대상인 사용자에게 후보곡 수정 알림을 생성한다. 삭제된 세션의 과거 응답만 남은 사용자는 제외한다. 기존 표시와 알림은 [후보곡 수정 알림](./nomination-update-notifications.md)의 2026-10-08 적용된 마이그레이션을 통해 DB 수정 시각을 공유한다.

- updateNomination: 기존 권한 검사를 통과한 후 원문 내용이 동일하면 DB 갱신을 생략한다. JSON 필드 순서, 화면용 타임스탬프 ID, 빈 선택 필드의 저장 표현 차이는 내용 변경으로 취급하지 않는다.
- saveNominationResponsesAction: 성공 결과는 { ok: true, updatedAt: string }, 실패 결과는 { ok: false, error: string }. 한 번의 저장에 같은 서버 시각을 사용하고 클라이언트에도 반환한다.

## 5. UI / UX

- 기본 목록: 나의 응답 옆에 주황색 응답 후 수정됨 배지.
- 간략 목록: 같은 의미의 주황색 아이콘과 접근성 레이블로 표시.
- 곡 상세 나의 응답: 마지막 응답 이후 글이 수정되었습니다 문구와 응답 다시 확인 버튼. 여러 세션에서는 재확인이 필요한 세션 이름도 표시한다.
- 가능 여부 저장 성공/실패 토스트는 하단 중앙에 표시해 상세/응답 모달의 닫기 버튼을 가리지 않는다. 모바일에서는 하단 고정 응답 버튼 및 safe area 위로 간격을 둔다.

## 6. 검증 결과

- 응답 이전/이후/동일 시각, 미응답, 세션별 시각 비교 검증.
- 실제 변경 및 동일 내용 저장, JSON 표현 차이 검증.
- 저장 성공은 서버 시각으로 갱신하고 실패는 안내를 유지하는지 검증.
- 상세 안내 문구와 기본/간략 목록 표시, 토스트 위치 검증.
- 관련 회귀 테스트, TypeScript 및 변경 파일 ESLint 실행.
