# 후보곡 수정 시 기존 응답자 알림

> **작성일자**: 2026-10-08  
> **작성자**: Codex  
> **상태**: 2026-10-08 연결된 DB 적용 완료 / 실제 푸시 수신 미검증

## 1. 배경 및 목적

응답한 후보곡의 원문이 바뀌면 응답을 다시 확인할 수 있도록 기존 응답자에게 알림을 제공한다. 곡 수정으로 응답 대상에서 제외된 사용자에게는 발송하지 않는다.

## 2. 요구사항

- 수정 후 곡의 필요 세션에 남아 있는 **이미 저장된 본인 응답** 중 다시 응답할 수 있는 세션이 하나 이상인 현재 공연 참여자만 수신한다.
- 세션 삭제, 추천 보컬 제외 또는 공연 배정 변경으로 기존 응답 세션이 모두 응답 대상에서 벗어나면 알림을 만들지 않는다. 과거에 다른 세션에 응답했다는 이유만으로 새로 추가된 세션에 대한 알림을 보내지 않는다.
- 배정 세션 별칭, 추천 보컬 지목, 공연에서 미배정인 자유 세션 판정은 lib/nomination.ts의 응답 대상 규칙을 따른다. 추천 보컬은 현재 참여자의 계정 ID 또는 공연자 ID로 연결하여 기존 JSON에 userId가 없어도 UI와 DB가 같은 대상 판정을 한다.
- 저장된 available/unavailable/undecided 응답 모두 포함한다. 저장한 응답이 없으면 제외한다. 곡 수정 시각보다 먼저 저장된 응답을 대상으로 한다.
- 수정자 본인을 제외한다. 인증 세션 없는 DB 직접 수정에서는 곡 등록자 계정을 수정자로 간주한다. 여러 세션/공연자 행이 있어도 계정당 한 번만 알림을 생성한다.
- 원문 내용이 실제로 변경된 UPDATE에만 알림을 만들고 시각/메타데이터만 수정하거나 내용이 같은 저장은 알림을 만들지 않는다.
- 인앱 알림은 수신 동의와 무관하게 저장하고, 푸시는 기존 동의·기기·재시도 정책을 따른다.

## 3. 데이터 모델

- 신규 마이그레이션: 20261008000000_notify_nomination_updated.sql. 기존 테이블/컬럼 유지.
- notifications.event_type CHECK에 nomination_updated 추가. 이벤트 키는 nomination-updated:<곡 ID>:<수정 시각의 UTC 밀리초 ISO 문자열>.
- 원문 변경 BEFORE UPDATE 트리거가 updated_at을 DB 현재 시각과 기존 시각 + 1ms 중 큰 값으로 설정한다. 같은 내용의 원문 UPDATE는 기존 시각을 유지한다.
- AFTER UPDATE 트리거는 수정과 수신자별 알림을 같은 트랜잭션에서 저장한다. 직접 SQL UPDATE도 적용된다.
- 내부 함수는 빈 search_path를 사용하고 PUBLIC/anon/authenticated 직접 실행을 금지한다. 기존 RLS/쓰기 권한은 유지한다.

## 4. Server Action

- updateNomination: 기존 권한/동일 내용 검사를 유지한다. UPDATE 결과의 DB updated_at으로 정확한 수정 이벤트 키를 만들고 Next.js `after` 콜백 안에서 processPendingPushNotifications를 호출해 해당 이벤트를 응답 이후에 발송한다. 사용자 화면 이동은 FCM 완료를 기다리지 않으며, 내용이 같은 저장은 발송 작업을 등록하지 않는다.
- 발송 작업 등록 실패와 백그라운드 발송 실패는 원문 저장을 실패로 처리하지 않는다. 저장된 outbox로 cron이 재시도한다. DB 직접 수정은 cron이 발송한다. 이번 응답 분리는 기존 트리거와 스키마를 유지하는 앱 코드 변경이다.

## 5. UI / 알림 문구

- 제목: [공연명] 선곡회의 후보곡 수정
- 본문: '곡명'의 내용이 수정되었습니다. 변경된 내용을 확인해주세요.
- 링크: /gigs/<공연 ID>/nominations?song=<곡 ID> (해당 후보곡 상세 열기)
- 기존 응답 이후 수정 배지/상세 안내 및 재저장 시 해제 동작을 유지한다.

## 6. 검증 및 적용 상태

- 사용자 요청에 따라 테스트를 작성하거나 실행하지 않았고 실제 알림을 시험 발송하지 않았다.
- 2026-10-08 gig_id 8의 미발송을 읽기 전용으로 점검했다. 앱 환경과 CLI의 연결 프로젝트가 일치하며, 원격 이력에 수정 알림 마이그레이션이 없고 수정 알림 행도 없었다.
- 적용 직전 후보곡 161은 2026-10-08 00:07:32(KST) 수정 시각, 응답 3건은 00:16:48(KST) 저장 시각이었다. 이미 저장된 세 세션은 현재 응답 대상이지만 응답 시각보다 곡 수정 시각이 앞서므로 당시 기준으로 재확인 대상은 아니었다. 기존 변경의 알림을 소급 생성하지 않는다.
- 적용 계획에서 대기 마이그레이션이 이 파일 1건뿐임을 확인하고 20261008000000_notify_nomination_updated.sql을 연결된 DB에 적용했다. migration list 재조회에서 로컬/원격 버전 일치를 확인했다.
- npm run types를 사용자 Windows 계정에서 다시 실행해 적용된 DB의 타입을 재생성했다. 공개 타입에는 nomination_session_matches 함수가 추가되었다. 이전 CodexSandboxOffline 계정의 CLI 자격증명 접근 실패는 실행 계정을 변경하여 해결했다.
- 실제 알림 생성과 기기 푸시 수신은 사용자의 다음 원문 수정에서 확인해야 한다. 응답한 계정이 수정자이면 본인 제외 규칙으로 생성하지 않는다. 앱 수정은 해당 이벤트를 즉시 처리하며 DB 직접 수정은 cron이 처리한다.
