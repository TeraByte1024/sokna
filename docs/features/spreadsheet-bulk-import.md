# 엑셀/스프레드시트 공연자 및 셋리스트 일괄 불러오기 (덮어쓰기) 명세서

> **작성일자**: 2026-09-18  
> **상태**: Completed  

---

## 1. 배경 및 목적 (Background & Objectives)
- 공연 관리자가 엑셀이나 구글 스프레드시트에 정리된 공연 참여자 명단 또는 세션 분배 결과표를 일일이 손으로 입력하는 번거로움을 해소합니다.
- 복사(Ctrl+C) 후 붙여넣기(Ctrl+V) 한 번으로 공연자와 셋리스트(곡명, 아티스트, 세션별 배정)를 일괄 등록하고 기존 내역을 안전하게 덮어쓰기(Replace)할 수 있도록 지원합니다.
- 파싱 중 발생하는 모호성(비인명 메모, 1인 다세션 vs 동명이인, 부원 DB 계정 매칭, 보컬 성별 구분)을 4단계 스마트 Conflict 해결 다이얼로그를 통해 쉽고 안전하게 해소합니다.

---

## 2. 지원 표 형식 및 헤더 동의어 사전

### 2.1 형식 1: 참여자 명단표 (공연자 전용)
- **컬럼 구성**: `기수 | 이름 | 세션` (순서 무관)
- **동작**: 참여 부원 목록을 추출하여 공연자 명단에 등록 (기수 정보로 부원 DB 자동 연동)

### 2.2 형식 2: 세션 분배 결과표 (공연자 + 셋리스트 동시 추출)
- **컬럼 구성**: `(곡 제목) | (아티스트 - 선택) | 보컬 | 기타1 | 기타2 | 베이스 | 키보드1 | 키보드2 | 드럼`
- **유연성**: 아티스트 컬럼이 생략된 표(예: `곡 | 보컬 | 기타1 ...`)도 자동으로 인식하여 2번째 컬럼이 보컬로 정상 처리됨.

### 2.3 헤더 동의어 사전
- **곡 제목**: `곡`, `곡명`, `곡제목`, `곡 제목`, `노래`, `제목`, `title`, `song`
- **아티스트**: `아티스트`, `가수`, `원곡자`, `원곡`, `artist` (오인 방지를 위해 `singer`는 제외)
- **기수**: `기수`, `대수`, `gen`, `generation` (`학번`은 제외)
- **이름**: `이름`, `성명`, `부원`, `부원명`, `멤버`, `name`, `member`
### 2.4 Global 세션명 통일 및 다중 컬럼 병합
- **기타 통일**: `기타1`, `기타2`, `일렉`, `일렉기타`, `어쿠스틱` 등은 모두 표준 global 세션명인 **`기타`**로 통일됩니다.
- **키보드 통일**: `키보드1`, `키보드2`, `건반`, `건반1`, `건반2`, `피아노`, `신디` 등은 모두 표준 global 세션명인 **`키보드`**로 통일됩니다.
- **곡별 세션 슬롯 자동 병합**: 동일 곡에서 `기타1`과 `기타2`에 각각 연주자가 지정된 경우 별도의 슬롯으로 쪼개지지 않고 하나의 `기타` 슬롯 내 멤버 배열(`["남채현", "김서율"]`)로 자동 병합됩니다. (키보드1, 키보드2도 `키보드` 슬롯으로 자동 병합)
- **표준 세션 순서 정렬**: 각 곡의 세션 슬롯은 `보컬` → `기타` → `베이스` → `키보드` → `드럼` 표준 순서로 자동 정렬됩니다.

## 3. 스마트 Conflict 해결 파이프라인

UI에서는 파싱된 데이터와 부원 DB(`users`)를 교차 검증하여 다음 순서로 충돌을 자연스럽게 해결합니다:

1. **등록 회원 세션 불일치 확인 (1단계)**
   - **대상**: 부원 DB(`users`)에 등록된 회원 중, 저장된 세션(`users.part`)과 엑셀에 입력된 세션(`excelPart`)이 상이한 경우 (예: DB `베이스` vs 엑셀 `기타`, 또는 다중 세션 배정)
   - **옵션**: `[users 저장 세션 ({userSavedPart})]` / `[엑셀 세션 ({excelPart})]` (기본값: 엑셀 세션)
   - 상단에 `[전체 엑셀 세션]` / `[전체 users 세션]` 일괄 지정 버튼 지원
2. **비인명 / 특수 텍스트 감지**
   - **대상**: `다 하세요~`, `전원`, `미정`, `공석`, `-` 등 단체어/문장형 텍스트
   - **옵션**: `[무시하기 (공연자 제외 & 슬롯 비움)]` (기본값) / `[공연자로 등록하기]`
   - 무시하기 선택 시 해당 항목은 이후 단계 평가에서 즉시 제외됩니다.
3. **중복된 이름 (1인 다세션 vs 동명이인)**
   - **대상**: 한 사람이 2개 이상의 서로 다른 세션을 맡고 있는 경우 (예: `김재윤`: 보컬, 기타)
   - **대사**: `"{이름} 님이 여러 세션({세션1}, {세션2})을 맡고 있습니다. 동일 인물인가요?"`
   - **옵션**: `[동일 인물 (세션 합산)]` / `[동명이인 (개별 분리)]`
4. **부원 DB 동명이인 / 계정 매칭**
   - **대상**: 동아리 부원 DB에 2명 이상의 동명이인이 있거나, 동명이인으로 분리된 경우
   - **옵션**: `[{계정 1}]`, `[{계정 2}]`, ..., `[미연동 (더미 유지)]`, `[직접 입력]` (기수/이메일 수동 지정 필드 제공)
   - **자동 연동**: 단일 회원이거나 기수가 정확히 일치하는 회원은 계정 매칭 단계를 거치지 않고 `users` 계정(`id`, `email`, `generation`)과 즉시 자동 연동(Linked)됩니다.
5. **보컬 성별 구분 (남보컬 vs 여보컬)**
   - **대상**: 보컬 세션을 맡은 인원 중 부원 DB에 `보컬(남)` / `보컬(여)` 구분이 없거나 더미인 경우
   - **옵션**: `[남보컬]` / `[여보컬]` / `[공통]`

## 4. 덮어쓰기 (Replace) 안전장치

- 최종 미리보기 단계에서 경고 배너 표시:
  `"확인 버튼을 누르면 현재 폼에 등록된 셋리스트 (N곡)와 공연자 명단 (N명)이 모두 삭제되고, 새 데이터로 완전히 교체(덮어쓰기)됩니다."`
- 사용자가 `[기존 내역 삭제 후 덮어쓰기 적용]` 버튼을 누르면 폼의 `performers` 및 `setlists` 상태가 갱신됩니다.
