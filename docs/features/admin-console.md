# 관리자 화면 재구성 명세

> 작성일자: 2026-09-30
> 상태: 구현 및 운영 DB 마이그레이션 적용 완료, 서버 배포 대기

## 1. 목적

관리자 업무를 가입·공연 신청 승인, 공연 관리, 회원(관리자) 관리의 세 화면으로 분리한다. 같은 내비게이션과 화면 구성 요소를 사용해 데스크톱과 모바일의 사용성을 맞춘다.

## 2. 화면과 권한

| 메뉴 | 경로 | 기능 |
| :--- | :--- | :--- |
| 가입/공연 신청 승인 | `/admin/approvals` | 완성된 가입 신청 승인·반려, 공연 참여 신청 승인·반려 |
| 공연 관리 | `/admin/gigs` 및 `/admin/gigs/[id]` | 공연별 확정 참여자, 신청 현황, 비고 조회 |
| 회원(관리자) 관리 | `/admin/members` | 승인 회원 검색·필터·정렬·정보 수정, 관리자 임명·해제 |

- `/admin`은 `/admin/approvals`로 이동한다. 모든 관리자 화면과 서버 액션은 검증된 계정 ID의 관리자 권한을 확인한다.
- 기존 알림의 `/admin/members` 링크 중 가입·공연 신청 알림은 새 승인 화면으로 옮긴다.
- 관리자 본문은 기존 최대 너비를 유지하고 가운데 정렬한다. 넓은 화면에서는 왼쪽 여백에 세로 메뉴를 고정한다. 여백이 좁으면 아이콘을 표시하고, 모바일·태블릿에서는 헤더 로고 왼쪽의 메뉴 버튼으로 왼쪽 drawer를 연다. drawer는 열고 닫을 때 옆으로 이동하고 배경은 부드럽게 나타나거나 사라지며, 움직임 줄이기 설정에서는 애니메이션을 생략한다.
- 세 화면은 같은 제목·설명, 요약 수치, 표, 상태 배지, 빈 목록·오류 안내를 사용한다.

## 3. 신청 처리

- 가입 신청은 기수와 세션을 작성한 `users.status = 'pending'` 행만 대기 목록에 표시한다. 승인·반려 로직은 기존 동작을 유지한다.
- 공연 참여 의사(`gig_rsvps.status`)와 관리자 검토 상태(`review_status`)를 분리한다. `going`이면서 `review_status = 'pending'`인 신청만 승인 대기 목록에 표시한다.
- `review_gig_rsvp`는 최신 `updated_at`을 확인하고 행을 잠근 뒤 승인 시 공연자를 생성하고 `approved`, 반려 시 신청을 보존하고 `rejected`로 바꾼다. 처리 관리자와 시각을 기록한다.
- 반려된 회원이 참여 신청을 다시 저장하면 `pending`으로 복귀한다. 상태 전환 알림을 새로 생성하며 세션·비고만 반복 저장한 대기 신청에는 알림을 중복 생성하지 않는다.
- 과거에 무시되어 삭제된 신청은 복원할 수 없다. 기존 공연자가 연결된 RSVP는 마이그레이션에서 `approved`로 보정한다.
- 일반 회원은 승인·반려 상태와 처리 정보를 직접 변경할 수 없고, 반려·승인 기록을 직접 삭제할 수 없다.

## 4. 공연 및 회원 조회

- 공연 관리에서 공연별 `performers`를 확정 참여자로 표시한다. `gig_rsvps`의 비어 있지 않은 `note`는 참여 의사와 검토 상태를 함께 표시한다. 직접 등록된 공연자는 신청 비고가 없을 수 있다.
- 회원 관리의 기본 목록은 승인 회원이다. 이름·이메일·기수·세션 검색, 기수·세션·관리자 여부 필터, 이름·기수·승인일 정렬을 제공한다.
- 관리자 임명·해제는 ID 기준으로 처리한다. 본인 권한과 마지막 관리자 권한은 해제할 수 없다.

## 5. 검증

- 관리자/일반 회원 직접 URL 및 액션 접근, 가입 승인·반려, 공연 승인·반려·재신청과 중복 알림 방지를 확인한다.
- 공연별 확정 참여자와 신청 비고, 회원 필터·정렬, 빈 목록·조회 오류, 모바일·다크 모드·키보드 조작을 확인한다.
- DB 변경 시 `docs/architecture/database-schema.md` 갱신 및 `npm run types` 실행, `npm run lint`, `npm test`, `npm run build`로 검증한다.
