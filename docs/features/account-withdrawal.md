# 회원 탈퇴 명세서

> **작성일자**: 2026-09-26  
> **상태**: Completed

## 1. 배경 및 목적
- 로그인한 회원이 `/profile`에서 본인의 계정을 직접 삭제할 수 있도록 합니다.
- 인증 계정만 삭제되거나 개인 데이터만 삭제되는 부분 실패를 방지합니다.

## 2. 세부 요구사항
- 프로필 하단의 `회원 탈퇴` 버튼으로 확인 창을 엽니다.
- 복구 불가, 계정·개인 알림·참가 신청 삭제, 공연·선곡 등 공유 기록 보존을 안내합니다.
- 확인 문구 `탈퇴`를 입력해야 최종 제출할 수 있습니다. 서버와 DB에서도 검사합니다.
- 요청에 사용자 ID를 받지 않고 검증된 세션의 본인만 삭제합니다.
- 관리자도 탈퇴할 수 있으나 마지막 관리자는 다른 관리자를 지정해야 합니다. 동시 탈퇴 시에도 관리자 확인과 삭제를 잠금으로 직렬화합니다.
- 처리 중 중복 제출을 막고, 실패하면 오류를 표시하여 재시도할 수 있습니다. 성공 시 `회원 탈퇴가 완료되었습니다.` 브라우저 알림을 표시하고, 사용자가 확인하면 현재 기기 세션을 정리한 뒤 홈으로 이동합니다.

## 3. 데이터 모델 변경
- 기존 테이블과 외래키는 유지하고 `public.delete_my_account(p_confirmation text)` RPC를 추가합니다.
- `SECURITY DEFINER`, 빈 `search_path`, 명시적 스키마를 사용합니다. `PUBLIC`, `anon`의 실행 권한을 회수하고 `authenticated`에만 부여합니다.
- `auth.uid()`에 해당하는 실제 인증 계정을 잠근 뒤 다음 작업을 단일 트랜잭션으로 처리합니다.
  1. 본인의 ID 또는 인증 계정 이메일에 대응하는 관리자 권한 삭제.
  2. 공연자 레코드는 보존하되 `user_id = null`, `name = '탈퇴 회원'`, `photo_url = null`로 변경.
  3. 본인의 기기 토큰(`profiles`)과 수신 알림(`notifications`) 삭제.
  4. `public.users` 삭제. 참가 신청, 선곡 응답 및 열람 시점은 기존 CASCADE로 삭제하고 알림 큐의 `triggered_by`는 기존 SET NULL로 해제.
  5. `auth.users` 삭제. 인증 세션·소셜 연결 등은 Auth 외래키에 따라 정리.
- 공연, 후보곡, 확정 셋리스트, 갤러리 및 공유 기록에 저장된 이름/사진 등은 일괄 삭제하지 않습니다. 공연자와 계정의 직접 연결 및 공연자 프로필 사진 링크는 해제합니다.
- 중간 오류 발생 시 모든 변경을 롤백합니다. 미인증·잘못된 확인 문구·마지막 관리자 요청은 데이터 변경 전에 거절합니다.

## 4. API / Server Action
### `deleteMyAccountAction(confirmation: string)`
- 위치: `app/profile/actions.ts`
- `auth.getUser()`로 사용자 검증 후 요청자 세션으로 RPC 호출.
- 결과: `{ ok: true } | { ok: false; error: string }`.
- DB 삭제 성공 후 로컬 세션 정리 및 공통 레이아웃 캐시 갱신. 후속 정리 실패를 계정 삭제 실패로 안내하지 않습니다.
- 서비스 키나 클라이언트가 지정한 삭제 대상 ID를 사용하지 않습니다.

## 5. UI / UX
- 기존 프로필 편집 폼과 분리된 탈퇴 영역 및 확인 다이얼로그.
- 키보드 포커스, 취소, 오류 안내, 처리 상태 및 중복 제출 방지 지원.
- 프로필 저장·푸시 설정 중 탈퇴 요청을 막습니다. 탈퇴 성공 후에만 미저장 변경 경고를 해제합니다.

## 6. 검증
- `tests/account-withdrawal.test.mjs`: 미인증, 확인 문구, RPC 실패, 마지막 관리자 안내, 성공 및 후속 정리 오류 등 서버 액션 테스트 11개 통과.
- `tests/account-withdrawal.sql`: 연결 DB에서 가상 계정으로 미인증·확인 문구 거부, 계정/기기/신청/응답 삭제, 후보곡과 공연자 보존, 다른 계정 보존, 트랜잭션 롤백, 삭제 계정 재호출 거부 검증 완료. 전체 ROLLBACK 후 가상 계정 0건 확인.
- 실제 수신자에게 알림이 발생하지 않도록 SQL 검증은 웹훅이 연결된 `notifications`·`setlists`에 데이터를 넣지 않습니다. 마지막 관리자 DB 분기는 기존 관리자를 변경하지 않고 서버 액션 오류 처리 및 SQL 로직 검토로 확인합니다.
- TypeScript, 변경 파일 ESLint 및 `npm run build` 통과.
- `npm run types`는 실행했으나 로컬 CLI 액세스 토큰 부재로 실패했습니다. Supabase 타입 생성 도구의 실제 RPC 시그니처를 반영했으며, 기존 로컬 명세의 타입은 유지했습니다.
- 마이그레이션 `20260926080436_add_account_withdrawal.sql`은 연결 DB에 적용 완료했습니다.
