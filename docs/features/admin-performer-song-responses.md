# 관리자 공연자별 곡 응답 현황

> 작성일자: 2026-10-05  
> 상태: 구현 완료

## 1. 목적

관리자가 세션을 선택한 뒤 공연자 순서 목록에서 한 명 또는 여러 명을 선택하여 곡 응답과 메모를 한 표에서 확인한다.

## 2. 요구사항 및 UX

1. `/admin/gigs/[id]`의 곡별 응답 현황에서 세션을 먼저 선택한다. 기존 공연자 선택 드롭다운 대신 `응답현황 공연자 순서` 목록에서 체크박스로 한 명 또는 여러 명을 선택한다. 선택한 사람만 1부터 번호를 부여하며 위·아래 버튼으로 순서를 바꿀 수 있다. 해제한 사람은 목록 아래에 번호 없이 표시하고 재선택하면 선택 목록 끝에 붙인다. 전체 선택은 현재 순서 뒤에 미선택자를 추가하고 전체 해제도 제공한다. 기본값은 정렬된 첫 세션과 전체 선택이다. 세션 변경 시 선택과 순서를 해당 세션의 전체 공연자 명단 순서로 초기화한다. 데스크톱과 모바일 모두 `세션 전체`는 제공하지 않는다.
2. 선택한 공연자·세션에 응답 가능한 세션이 있는 후보곡만 등록순으로 `곡 제목 · 아티스트 | 응답 현황 | 메모` 표에 표시한다. 해당 곡이 없으면 빈 목록 안내를 표시한다. 데스크톱에서는 제목과 아티스트를 한 줄에 표시하고 셀 세로 여백을 줄인다.
   - 공연자 전체를 선택하면 선택 세션에 응답 가능한 공연자 전체의 상태·메모를 표시한다.
   - 공연자 한 명 또는 여러 명을 선택하면 선택한 공연자의 선택 세션만 표시한다. 한 명도 선택하지 않으면 선택 안내와 빈 표를 표시한다. 세션 선택지는 후보곡의 필요 세션 합집합이며 기존 세션 정렬을 적용한다.
3. 응답 현황은 기존 `getEligibleSessionsForUser` 규칙(배정 세션, 추천 보컬, Local Custom)을 사용한다. 세션의 공연자 목록은 전체 후보곡 중 해당 세션에 응답 가능한 공연자의 합집합이다. 가능/불가능/미응답은 모든 화면에서 상태색 배지와 아이콘으로 구분하며 접근성 레이블·툴팁·상세 대화상자로 이름과 상태를 확인한다.
4. 응답 가능한 세션이 없는 곡은 목록에서 제외한다. 응답 가능한 세션이 있지만 아직 미응답인 곡은 계속 표시한다. 연결된 계정이 없는 공연자도 배정에 따라 응답 가능한 곡을 표시하며 `계정 미연결`로 안내한다. 이름으로 다른 회원의 응답을 연결하지 않는다. 모든 화면에서 메모가 있을 때만 아이콘을 표시하며 없으면 빈칸으로 둔다. 메모 버튼을 누르면 응답 상세 대화상자에서 내용을 확인한다.
5. 데스크톱 응답 표의 행 클릭 또는 곡 제목 링크로 `/gigs/[id]/nominations?song=[곡 ID]`에 이동하면 기존 곡 상세 서랍을 바로 연다. 링크는 키보드와 새 탭 열기를 지원한다. 잘못된 ID나 다른 공연의 곡은 열지 않는다. 모바일 응답 표는 아래 상세 대화상자 규칙을 따른다.
6. 공연자 없음, 후보곡 없음, 조회 실패를 별도로 안내한다. 확정 참여자는 아래 공연자 관리 폼에서 조회·수정한다. 신청 비고는 이 표의 비고 컬럼으로 통합하고 별도 신청 비고 표는 제거한다. 연동된 참여자는 연동 상태만 표시하고 변경·해제 버튼을 두지 않는다. 미연동 참여자의 연동 버튼은 유지한다.
7. 상단 메뉴와 본문을 `기본 정보 → 선곡회의 곡 목록 → SETLIST 관리 → 공연자 관리 → 공연자별 곡 응답 현황` 순서로 배치한다. 선곡회의 곡 목록은 등록순 제목·아티스트 한 줄 표와 곡 상세 링크, 선곡회의 열기 버튼을 제공한다. 기본 정보·SETLIST·공연자 관리는 같은 수정 폼을 유지한다. 상단 바로가기는 페이지 내 스크롤로 각 섹션에 이동하며 이탈 확인을 띄우지 않는다. 기존 가져오기·엑셀·세션 순서·계정 연결·포스터·저장 검증·이탈 방지 기능을 유지한다.
8. 저장 성공 후 `/admin/gigs/[id]`를 다시 조회해 공연 정보, 공연자, 응답 현황을 최신 상태로 표시한다. 취소는 관리자 공연 목록으로 이동하며 변경사항이 있으면 기존 이탈 확인을 적용한다. 응답 행 이동도 곡 제목 링크의 클릭을 사용해 이탈 확인을 거친다.
9. 모바일에서는 5개 바로가기를 관리자 drawer에 표시한다. 참여자 표는 이름·기수·세션을 표시하고 인라인 추가/삭제를 생략하며 비고가 있을 때 아이콘만 표시한다. 행 상세 대화상자에서 정보를 조회하고 세션 편집·미연동 계정 연동을 수행한다. 공연자 삭제는 확인 후에만 폼에서 제외하며 최종 저장·이탈 방지 규칙은 유지한다. [모바일 참여자 관리](../pages/16-admin-gigs.md) 명세를 따른다.
10. 선곡회의 곡 목록은 행 전체를 누르면 곡 제목 링크를 통해 상세로 이동한다. 텍스트 선택 및 링크 자체 클릭은 중복 처리하지 않고 기존 변경사항 이탈 확인을 유지한다.
11. 모바일 응답 표는 고정 열 너비로 가로 스크롤을 없앤다. 곡 제목은 말줄임하고 아티스트는 생략한다. 세션 선택의 `세션 전체`를 제거하고 첫 세션을 기본 선택한다. 응답은 원 없는 선형 초록 체크(가능)·빨강 X(불가능)·회색 원 안의 물음표(미응답) 공통 아이콘으로 표시하며 세션 이름은 표에서 생략한다. 선곡회의와 같은 상태 아이콘을 둥근 직사각형 상태색 배지로 한 번만 감싸며 [공통 아이콘 명세](./ui-icons.md)를 따른다. 계정 미연결은 회색 아이콘과 접근성 레이블로 구별하며 해당 세션이 없으면 곡을 목록에서 제외한다. 메모는 있을 때만 아이콘으로 표시한다.
12. 모바일 응답 표의 행·제목·메모를 누르면 전체 제목·아티스트·공연자·기수·세션·응답·메모를 읽는 대화상자를 연다. `곡 상세 열기`는 modal을 먼저 닫고 기존 곡 링크를 클릭하여 이탈 확인과 상세 바로가기를 유지한다.
13. 요약은 이름이나 세션 이름 없이 `M곡 중 N곡 응답`으로 표시한다. M은 전체 후보곡 수이며 N은 선택 공연자의 모든 응답 가능 세션에 가능·불가능 응답이 완료된 곡 수이다. 선택 세션과 무관한 전체 곡 집계 범위를 유지한다. 여러 명 선택 시 선택한 사람 중 해당 곡에 응답 가능한 사람 모두의 응답이 완료되어야 한 곡으로 센다. 응답할 세션이 없는 곡·계정 미연결·미저장·미정은 완료 수에 포함하지 않는다. 선택한 사람이 없으면 응답 완료 수는 0이다.
14. 응답 표는 모든 화면에서 고정 레이아웃으로 곡 제목을 말줄임한다. 모바일 제목 열은 32%, 메모 열은 48px를 사용하며 남은 폭에 응답을 표시한다. 데스크톱 응답 열은 5개 아이콘 최대 너비 180px와 좌우 여백을 합한 212px, 메모 열은 64px로 제한하고 남는 폭은 제목에 배정한다. 응답 열 제목·도움말은 왼쪽 정렬하고 고정 5열 그리드만 오른쪽으로 정렬하여 메모 열 왼쪽에 붙인다. 그리드 내부 공연자 번호와 순서는 유지한다. 모든 화면에서 메모 버튼은 공연자 비고와 같은 작은 `MessageSquare` 아이콘·연한 배경·둥근 테두리 스타일을 사용하며 상세 대화상자를 연다. 데스크톱 표에도 메모 본문이나 빈 메모의 대시를 표시하지 않는다.
15. 곡 응답 상세 대화상자는 선곡회의 세션 응답 대화상자·곡 상세의 디자인을 따른다. 둥근 모달의 연한 헤더에 참여자 아이콘·제목·곡 정보를 표시하고 본문만 스크롤한다. 각 응답은 둥근 카드에서 상태 배지 → 기수·이름 → 세션 배지 순으로 표시한다. 메모는 있을 때만 메시지 아이콘과 연한 말풍선으로 표시하며 상세 조회 목적에 맞게 전문과 줄바꿈을 유지한다. 하단에는 닫기·곡 상세 열기 버튼을 배치하고 기존 이탈 확인 동작을 유지한다.
16. 선택한 공연자만 사용자 지정 목록 순서로 1부터 번호를 부여한다. 선택·해제·순서 변경 시 빈 번호 없이 다시 번호를 부여하며 한 명 선택 시 이전 위치와 무관하게 1번으로 첫 슬롯에 표시한다. 현재 선택 안에서는 응답 배열 순서·응답 상태·곡별 추천 여부에 따라 번호를 바꾸지 않는다. 모든 곡에서 1~5번은 첫 줄, 6~10번은 둘째 줄로 위치를 유지한다. 선택한 사람 중 해당 곡의 세션에 참여하지 않는 사람의 자리만 빈 슬롯으로 유지한다. 미선택자의 자리는 예약하지 않는다. 마지막 줄은 남은 인원만 표시한다.
17. `응답 현황` 컬럼명 옆 도움말 버튼을 누르면 현재 선택된 공연자의 번호·기수·이름 대응 목록을 modal dialog로 표시한다. 번호는 상단 순서 목록 및 응답 툴팁·접근성 레이블에서도 동일하게 사용한다. 선택·순서·세션이 바뀌면 도움말 목록도 같은 기준으로 갱신한다. 선택·순서는 조회용 화면 상태이며 공연자 명단이나 저장 payload를 변경하지 않는다.
18. 세션 선택은 관리자 회원 관리 필터와 같은 공통 `DropdownMenu`·`DropdownMenuRadioGroup`·`DropdownMenuRadioItem`과 outline `Button`을 사용한다. 선택값과 화살표를 표시하고 메뉴는 trigger 너비에 맞추며 긴 목록은 화면 안에서 스크롤한다. 세션 정렬은 `sortSessionParts` 순서를 유지하되 `isLocalCustomSession`으로 판별한 공연 전체에 미배정된 로컬 커스텀 세션은 마지막 그룹으로 이동한다. 기본 세션과 별칭은 배정자가 없어도 앞 그룹을 유지한다. 첫 번째 비커스텀 세션을 기본값으로 사용하며 커스텀 세션만 있으면 첫 커스텀 세션을 선택한다.
19. 공연자 순서 목록은 세로 여백 6px와 순서 버튼 28px로 행 높이를 줄인다. 선택을 해제해도 순서 변경 버튼의 공간을 유지하여 행 높이와 이름 영역의 폭이 바뀌지 않도록 한다. 미선택자의 순서 변경 버튼은 보이지 않게 하고 비활성화하여 키보드 포커스와 접근성 탐색에서 제외한다.

## 3. 데이터 및 권한

- 기존 테이블과 RLS 유지. 스키마 변경 없음. 기존 `updateGig`의 저장 계약을 유지하고 관리자 공연 목록·상세 캐시 갱신을 추가한다.
- 관리자 레이아웃의 권한 검증을 유지하며 서버에서 해당 공연의 `nominations`와 중첩 `nomination_responses`를 조회한다.
- note는 곡별 `nomination_responses.comment`이며 공연 참여 신청의 `gig_rsvps.note`와 구별한다.
- 공연자 표의 비고는 같은 공연의 신청 비고를 회원 ID로 연결하는 읽기 전용 정보이다. 이름·정렬 순서로 연결하지 않는다. 폼 상태나 저장 payload에 포함하지 않으며 기존 RSVP 데이터와 RLS를 유지한다. 선곡회의 메모 칩의 아이콘·연한 배경·둥근 테두리·말줄임·툴팁을 따른다.
- 곡 상세 이동은 기존 선곡회의 인증·공연 공개 범위 검증을 따른다.
- 공연 수정 데이터 로더는 공연자 또는 SETLIST 조회에 실패하면 수정 폼 대신 오류를 표시한다. 실패한 조회를 빈 명단으로 저장할 수 없도록 한다.
- 기존 `/gigs/[id]/edit`는 관리자 확인 후 `/admin/gigs/[id]#gig-basic-info`로 이동한다. 비관리자는 기존처럼 공연 상세로 이동한다.

## 4. 구현 및 검증

- `components/admin/performer-song-responses.tsx`: 공연자 선택과 곡별 표.
- `components/admin/response-performer-legend-dialog.tsx`: 세션별 응답 번호와 공연자 대응 안내.
- `app/admin/gigs/[id]/page.tsx`: 서버 데이터 조회와 표 연결.
- `components/nominations/nomination-panel.tsx`: `song` URL 파라미터에 해당하는 상세 서랍 초기 표시.
- 검증: 공연자 전환, 복수 세션 응답/메모 분리, 미응답·계정 미연결·빈 목록, 곡 상세 링크, lint·테스트·빌드.
