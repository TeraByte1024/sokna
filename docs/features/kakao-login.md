# 카카오 로그인 명세서

> **작성일자**: 2026-09-27
> **상태**: 코드·DB 보호 규칙 구현 및 운영 Kakao 활성화 완료. 실제 로그인은 `KOE205`(`account_email` 동의항목 미설정)로 차단됨. 이메일 동의 설정 보완·실제 인증 검증 및 운영 코드 배포 확인 필요.

## 1. 배경 및 목적

카카오계정으로 로그인·가입하고, 기존 소크나 계정의 추가 로그인 수단으로 카카오계정을 연결하거나 해제합니다. 기존 Google·이메일 로그인, 회원 승인 및 사용자 ID 기반 권한을 유지합니다.

## 2. 세부 요구사항

### 사용자 흐름

1. 로그인·회원가입 화면의 노란색 카카오 로그인 버튼에서 카카오 인증을 시작합니다.
2. 기존 PKCE 콜백에서 세션을 교환합니다. 필수 부원 정보가 없는 신규 사용자는 기존 프로필 작성·승인 절차를 거칩니다.
3. 기존 회원은 프로필에서 카카오 계정을 추가할 수 있습니다. 다른 이메일이어도 인증한 계정을 같은 회원 ID의 로그인 수단으로 연결합니다.
4. 프로필의 Google·카카오 항목에서 대상 계정을 확인한 뒤 연결을 해제합니다. 마지막 사용 가능한 로그인 수단은 유지합니다.

### 인증·운영 조건

- Supabase의 `provider: "kakao"`를 사용합니다. 자체 토큰 저장소, 카카오 JavaScript SDK 및 별도 계정 병합은 추가하지 않습니다.
- 일반 로그인과 연결 모두 `prompt: "select_account"`로 카카오계정 선택을 요청합니다. 카카오톡 인앱 브라우저에서 지원하지 않는 재인증용 `prompt: "login"`은 사용하지 않습니다. 단일 세션에서는 계정이 바로 선택될 수 있습니다. [카카오 인가 코드 API](https://developers.kakao.com/docs/ko/kakaologin/rest-api#request-code)
- 일반 버튼은 공개 Auth `/settings`의 `external.kakao`를 먼저 확인합니다. 아직 활성화되지 않았으면 현재 화면에서 안내하고 OAuth URL로 이동하지 않습니다. SDK의 URL 생성 성공을 운영 설정 완료로 취급하지 않습니다.
- 카카오의 REST API 키와 Client Secret은 Supabase 제공자 설정에만 저장합니다. 앱 클라이언트나 저장소에 비밀키를 넣지 않습니다.
- 카카오 로그인·연결은 이메일(`account_email`)만 요청합니다. 닉네임(`profile_nickname`)·프로필 사진(`profile_image`)은 요청하지 않으며 카카오 콘솔에서도 두 동의항목을 **사용 안 함**으로 설정합니다. 회원 이름은 기존 부원 정보 작성 화면에서 직접 입력합니다. 이메일 없는 카카오 가입은 활성화하지 않습니다.
- 운영 Auth `v2.197.0`의 기본 scope에는 이메일·닉네임·사진이 포함되므로, 두 진입점 모두 공통 `KAKAO_AUTH_QUERY_PARAMS`의 `queryParams: { prompt: "select_account", scope: "account_email" }`을 사용해 기본값을 덮어씁니다. 기본값에 추가하는 복수형 `options.scopes`는 사용하지 않습니다. Auth는 단수형 `scope`를 OAuth 옵션으로 전달하고 OAuth 라이브러리는 기본 scope 이후 해당 값을 적용합니다. [Kakao 기본값](https://github.com/supabase/auth/blob/v2.197.0/internal/api/provider/kakao.go), [Auth 전달 경로](https://github.com/supabase/auth/blob/v2.197.0/internal/api/external.go), [예약 매개변수](https://github.com/supabase/auth/blob/v2.197.0/internal/api/custom_oauth_admin.go), [OAuth 옵션 적용 순서](https://github.com/golang/oauth2/blob/v0.36.0/oauth2.go)
- scope 축소 자체는 과거에 동의한 항목이나 이미 저장된 Auth 메타데이터를 삭제하지 않습니다. 제공자 활성화 전에 콘솔 동의항목을 함께 설정합니다.
- 카카오의 이메일 확인 및 유효성 결과가 모두 참일 때 Supabase는 `email_verified: true`를 기록합니다. 다른 수단의 해제 후 남길 카카오 identity는 공백이 아닌 이메일과 명시적인 확인 값 true가 필요합니다.
- 카카오 계정에 이미 연결된 별도 소크나 회원의 기록을 병합하지 않습니다. 동일 확인 이메일의 자동 연결은 Supabase 규칙을 따릅니다.
- 서비스의 연결 해제는 Supabase identity 해제입니다. 카카오 전체 서비스 연결 해제나 카카오톡 로그아웃, 다른 기기의 세션 폐기를 뜻하지 않습니다.

## 3. 데이터 모델 변경

- 기존 앱 테이블과 컬럼, `auth.users.id` 및 외래키를 유지합니다.
- `20260927040000_support_kakao_identities.sql`로 마지막 로그인 수단 보호를 Google·카카오 모두에 적용합니다. 같은 부모 사용자 행을 잠근 뒤 사용 가능한 대체 수단을 검사합니다.
- Google의 기존 판정과 확인된 이메일 identity 판정은 유지합니다. 카카오의 확인 여부 및 이메일 조건은 서버 helper와 DB 트리거에 동일하게 적용합니다.
- 이전 대표 이메일 동기화 트리거와 ID 기반 관리자 권한은 유지합니다. 전체 계정 삭제와 Auth의 자동 연결 교체를 방해하지 않아야 합니다.
- 상세 적용 상태는 [DB 스키마 명세](../architecture/database-schema.md)를 따릅니다.

## 4. API / Server Action

- `startSocialIdentityLinkAction(expectedUserId, provider)`: `google | kakao` allowlist, 검증된 사용자 ID 대조, 같은 origin 콜백, 일회성 컨텍스트 쿠키와 PKCE를 사용합니다.
- `unlinkSocialIdentityAction(expectedUserId, identityId)`: 현재 사용자에게 속한 Google·카카오 identity만 해제합니다. 서버에서 대체 수단을 다시 검증하고, 성공 후 세션·프로필·관리자 목록을 갱신합니다.
- `lib/auth/social-providers.ts`: 지원 제공자, 타입 가드, 사용자 표시명 및 이메일만 요청하는 공통 카카오 OAuth 매개변수.
- `lib/auth/provider-availability.ts`: 공개 프로젝트 설정을 사용해 활성화 상태 조회. 5초 타임아웃, 캐시 미사용, 비밀키·사용자 토큰 불필요.
- 콜백 경로·일회성 쿠키·세션 전환 방어는 기존 [로그인 수단 명세](./login-methods.md)를 따릅니다. 오류 문구는 제공자 공통으로 처리합니다.

## 5. UI / UX

- 기존 Google 로그인과 나란히 카카오 로그인 버튼을 제공합니다. 노란색 `#FEE500`, 검정 말풍선과 텍스트 등 [공식 버튼 규정](https://developers.kakao.com/docs/ko/kakaologin/design-guide)을 따릅니다.
- 카카오 말풍선은 공식 벡터 리소스의 형태를 재사용하며, 인접 텍스트로 의미를 전달하는 장식 SVG는 aria-hidden입니다.
- 프로필은 두 제공자를 이름·로고로 구분하며, 선택한 제공자의 추가 버튼에만 진행 상태를 표시합니다.
- 해제 확인창은 실제 대상 제공자와 이메일을 표시합니다. 같은 이메일의 다른 수단이 남으면 다음 소셜 로그인에서 자동 재연결될 수 있음을 안내합니다.
- 연결·해제의 기존 중복 방지, 미저장 프로필 보호와 입력 보존을 유지합니다.

## 6. 테스트 및 검증

- Google 기존 회귀, 카카오 로그인·연결의 이메일 전용 scope 및 현재 origin 콜백, 미인증·계정 변경·지원하지 않는 제공자 차단. 두 요청에 닉네임·사진 scope나 복수형 options.scopes가 없는지 검증합니다.
- 공개 설정 비활성·조회 실패·OAuth 시작 실패·예외·중복 클릭 및 재시도.
- Google/카카오 혼합 목록·추가/해제, 미확인 또는 이메일 없는 카카오 대체 수단 차단.
- DB 혼합 제공자 보호, 마지막 카카오 차단, 이메일 충돌 롤백과 계정 탈퇴.
- 전체 자동 테스트, TypeScript·빌드, 변경 코드 ESLint 및 화면 검증.
- 실제 Google·카카오 인증 후 동일 사용자 ID·승인·기록 유지 확인은 제공자 설정 후 수행합니다.

## 7. 외부 설정 및 현재 상태

2026-09-27 사용자가 Kakao 제공자를 등록한 뒤 운영 공개 Auth 설정의 `external.kakao = true`와 기존 `external.google = true`를 재확인했습니다. 이메일 전용 인가 URL과 로그인 전 페이지 HTTP 200, 취소 시 복귀 콜백을 확인했지만 이 사전 점검은 실제 계정의 동의항목 사용 가능 여부를 검증하지 않았습니다. 이후 사용자가 실제 로그인을 시도한 화면에서 `KOE205`와 미설정 동의항목 `account_email`을 확인했습니다. 제공자는 활성화되어 있으나 이메일 동의항목 설정이 완료되지 않아 실제 인증이 차단된 상태입니다. 이메일만 요청하는 코드와 scope는 유지하며, [카카오 설정 절차](../maintenance/environment-setup.md#27-카카오-로그인-설정)에 따라 동의항목 설정을 보완한 뒤 재검증합니다. 기존 운영 로그인 HTML 조회에는 카카오 버튼이 없어 코드 배포 확인도 남아 있습니다. 토큰 교환·로그인 성공 및 계정 연결·해제는 아직 검증하지 않았습니다.

### 2026-09-27 검증 결과
- 이메일 전용 요청으로 수정한 뒤 일반 로그인·수동 연결 인증 테스트 54개, TypeScript 및 변경 코드·테스트 ESLint를 통과했습니다. 두 경로의 단수형 scope 값과 닉네임·사진 scope 제외를 검증했습니다. 실제 계정으로 보는 카카오 동의 화면은 아직 검증하지 않았습니다.
- 전체 자동 테스트 430개, 프로덕션 빌드 통과. 이후 추가한 공개 설정 조회·브라우저 뒤로가기 검증을 포함한 인증 테스트 54개도 통과했고, 최종 TypeScript·변경 코드 ESLint·diff 검사를 마쳤습니다.
- 격리 SQL 18개 검증으로 Google·카카오 혼합 수단 보호, 이메일 충돌 롤백, 자동 연결 교체 및 회원 탈퇴를 확인했습니다. 실제 독립 DB 세션 경합과 제공자 인증 E2E는 수행하지 않았습니다.
- 모바일 320px·390px, 데스크톱 및 다크 모드에서 실제 컴포넌트·Tailwind CSS를 사용하여 로고·긴 이메일·버튼·해제 확인창을 확인했습니다.
- 운영 DB에 040000 마이그레이션만 적용하고 이력·새 보호 트리거 활성화·이전 트리거 제거·함수 권한을 재조회했습니다. 관리자 7명의 ID·이메일 정합성은 그대로 유지됩니다.
- 운영 Auth health 조회 결과 v2.197.0을 확인했습니다. 로컬 CLI 캐시의 v2.188.1 값 대신 실제 버전의 소스를 기준으로 scope·이메일 검증·연결 해제 동작을 점검했습니다.
- 사용자 제공자 등록 후 공개 Auth 설정 HTTP 200에서 Kakao·Google 활성화를 확인했습니다. 로컬·운영 복귀 주소 각각에 대해 일반 로그인과 연결용 콜백 URL을 넣은 인증 시작 요청 4개가 카카오 인가 URL로 HTTP 302 응답했고, scope는 정확히 `account_email`, prompt는 `select_account`, 제공자 콜백은 등록할 Supabase Auth 주소였습니다.
- 인증 요청을 즉시 취소하여 네 요청 모두 원래 origin과 `/auth/callback`으로 HTTP 302 복귀하고, 연결용 쿼리의 intent·nonce가 보존됨을 확인했습니다. 연결용 검증은 redirect allowlist 검증이며, 로그인한 사용자의 실제 `linkIdentity` 실행이나 계정 연결 성공 검증은 아닙니다.
- 사전 점검에서 카카오 인가 엔드포인트가 `accounts.kakao.com/login`으로 이동하고 HTTP 200을 반환했습니다. 그 로그인 전 응답에는 KOE 오류 코드가 없었지만, 실제 사용자 인증·동의·Secret을 이용한 토큰 교환은 수행하지 않았으므로 동의항목 설정 완료를 의미하지 않습니다.
- 이후 사용자 실제 로그인 화면에서 `KOE205`와 미설정 동의항목 `account_email`을 확인했습니다. 이메일 동의 설정 보완 후 실제 인증·동의·토큰 교환부터 다시 확인해야 합니다.
- 로컬·운영 로그인 페이지 모두 HTTP 200입니다. 로컬 HTML에는 카카오 로그인 버튼이 있고 운영 HTML에는 아직 없습니다. 운영 앱 코드 배포와 실제 카카오 로그인·연결·해제는 남아 있습니다.
2026-09-27 DB 적용 후 npm run types를 완료했습니다. 일시적인 CLI TLS 연결 오류는 재시도로 해소했으며 재생성된 공개 타입 내용은 기존과 동일합니다.
