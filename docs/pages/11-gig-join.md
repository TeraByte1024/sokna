# 11. 공연 참가 신청 다이얼로그 [회원 전용]

## 1. 개요 및 접근 권한
- **URL 경로**: `/gigs/[id]`의 `공연 참여` 버튼. 기존 `/gigs/[id]/join`은 `/gigs/[id]?join=true`로 리다이렉트.
- **대상 사용자**: **관리자 승인이 완료된 회원 및 관리자 전용**
- **목적**:
  - 공연 기본 정보(제목, 일시, 장소)와 **선곡회의 일정/장소**를 포스터 없는 카드로 확인.
  - 해당 공연에 대한 본인의 참여 여부(`참여`, `불참`, `미정`) 및 희망 세션 파트, 전달 메모를 제출 및 수정.
- **보안 및 권한 정책**:
  - `/gigs/[id]/join`은 상세의 `?join=true`로 이동합니다. 상세의 공개 범위에 따라 내용을 제공하며, 승인 완료 회원·관리자에게만 신청 다이얼로그를 엽니다.
  - 비로그인·미신청·승인 대기·반려 계정은 전체 공개 공연도 참가 신청할 수 없습니다. 서버 액션과 DB INSERT/UPDATE RLS에서 같은 제한을 적용합니다.

## 3. 사용자 인터랙션 및 UX 흐름 (Step-by-Step)

1. **회원 권한 확인**:
   - 공유된 참가 신청 링크는 공연 상세로 이동합니다. 전체 공개 공연은 누구나 볼 수 있지만 신청 UI는 승인 완료 회원·관리자에게만 표시합니다.
   - 회원 공개 공연은 가입 승인이 완료돼야 열람할 수 있고 비공개 공연은 관리자만 접근할 수 있습니다.
2. **공연 및 선곡회의 일정 확인**:
   - 상단 카드에서 공연 타이틀, 공연 일시뿐만 아니라 **선곡회의 일시**와 공연/회의 장소를 확인합니다.
3. **참여 여부 선택**:
   - 최초 신청과 무시된 신청은 아무 상태도 선택되지 않으며 선택 전 저장할 수 없습니다.
   - **참여 (Going)**: 희망 세션 칩을 여러 개 선택할 수 있고, 선택한 칩을 다시 누르면 해당 세션만 해제됩니다. 프로필 세션이 있으면 처음에 선택되며, 없으면 직접 선택해야 합니다. 세션 칩은 이름 길이에 따라 폭이 달라지고 줄바꿈됩니다. 점선 테두리의 연한 `+ 직접 입력` 칩을 클릭하면 같은 자리에서 별도 폭의 텍스트 필드로 바뀝니다. 세션 이름을 입력하고 Enter를 누르거나 포커스를 벗어나면 선택된 세션 칩으로 확정되며, 이어서 직접 입력을 반복할 수 있습니다. 빈 입력은 칩으로 만들지 않고 접으며, 쉼표가 포함된 입력은 안내 후 추가하지 않습니다. 중복 이름은 하나만 유지하며, 직접 추가한 세션은 공용 기본 목록에 등록되지 않습니다. 저장 후 재접속 시 선택된 모든 세션을 복원합니다.
   - 참여를 선택했을 때만 세션 칩 아래에 관리자 승인 후 공연 참여자로 등록된다는 안내를 표시합니다.
   - **불참 (Not Going)** 및 **미정 (Undecided)**: 세션 선택은 숨기고 비고 메모(선택)를 작성할 수 있습니다.
4. **신청 제출 및 수정 (`submitGigRsvp` Action)**:
   - `[저장]` 버튼 클릭 시 로딩 스피너 활성화 (`pending === true`).
   - 참여 신청은 세션을 하나 이상 선택해야 저장할 수 있습니다. 서버는 반복 제출된 `part` 값을 공백 제거·중복 제거 후 `gig_rsvps.part`에 저장합니다. 저장 형식은 기존 공연자 파트와 같은 쉼표 구분 문자열입니다. `(gig_id, user_id)` Unique 기준으로 레코드가 UPSERT됩니다. 불참·미정은 `part = null`입니다.
   - 제출 완료 시 토스트 알림이 노출됩니다. 참여는 **승인 대기**이며, 승인 전에는 상태/세션/메모를 수정할 수 있습니다. 승인 대기 중 버튼은 시계 아이콘으로 표시합니다.
   - 이미 `performers`에 등록된 회원은 신청 다이얼로그 및 서버 액션 재제출이 차단됩니다. 비공개 공연 접근 제한도 서버에서 확인합니다.
5. **관리자 확인 연동**:
   - 관리자 페이지(`/admin/members`)의 **[참가 신청 현황]**에서 `공연제목 | 이름 | 기수 | 신청세션 | 비고 | 승인 | 무시` 순서의 한 줄 표로 표시합니다. 승인 대기 칩은 제거하며 미정 응답은 명단과 집계에서 모두 제외합니다.
   - **초록 체크(승인)**: 신청한 모든 세션을 공연자 `part`에 그대로 등록한 뒤 LINEUP에 반영합니다. 신청자의 `공연 참여` 버튼은 초록 체크로 비활성화하며 히어로/모바일 양쪽에서 사라지지 않습니다.
   - **빨간 휴지통(무시)**: RSVP를 삭제합니다. 신청자는 미신청 버튼과 미선택 다이얼로그로 돌아가 다시 신청할 수 있습니다.
   - 승인/무시는 `going` 신청에만 제공하며, 승인된 회원은 대기 명단에서 제외합니다. 변경되거나 이미 처리된 신청은 중복 처리하지 않습니다.
   - 다른 사용자의 열려 있는 화면은 재방문/새로고침 시 갱신됩니다.
6. **다이얼로그 닫기**:
   - 취소, 닫기, 배경 클릭 또는 Escape로 닫습니다. 저장하지 않은 내용은 다음에 열 때 저장된 RSVP 상태로 초기화합니다.

## 4. UI 상태 (States)

| 상태 | 화면 표시 및 처리 |
| :--- | :--- |
| **비로그인 (Unauthenticated)** | 서버 사이드에서 로그인 페이지로 즉시 강제 리다이렉트 (정보 은닉) |
| **최초 접속 / 무시 후** | 참여 여부 미선택, 프로필 파트가 있으면 선택, 참여 시 세션 한 개 이상 선택해야 저장 가능 |
| **재접속/수정 (Existing RSVP)** | 이전 선택 상태/모든 세션/메모 복원, `[저장]` 버튼 |
| **승인 대기** | 시계 아이콘, 신청 수정 가능 |
| **공연자 등록 완료** | 초록 체크 아이콘과 비활성화된 `공연 참여` 버튼 유지, 다이얼로그 열기 차단 |
| **제출 중 (Pending)** | 버튼 비활성화 및 로딩 스피너 작동 |
| **제출 완료 (Success)** | 토스트 알림 및 최신 데이터 반영 |
