# 11. 공연 참가 신청 페이지 (`/gigs/[id]/join`) [회원 전용]

## 1. 개요 및 접근 권한
- **URL 경로**: `/gigs/[id]/join`
- **대상 사용자**: **로그인한 동아리 회원 전용**
- **목적**:
  - 관리자가 생성한 공연 참가 신청 링크를 통해 접속하여 공연 기본 정보(포스터, 제목, 일시, 장소)와 **선곡회의 일시**를 확인.
  - 해당 공연에 대한 본인의 참여 여부(`참여`, `불참`, `미정`) 및 희망 세션 파트, 전달 메모를 제출 및 수정.
- **보안 및 권한 정책**:
  - **비회원(비인증) 접근 완전 차단**: 비로그인 사용자가 직접 링크로 접속할 경우 공연 및 선곡회의 정보가 전혀 노출되지 않으며, 서버 사이드에서 즉시 로그인 페이지(`/auth/login?redirect=/gigs/[id]/join`)로 리다이렉트됩니다.
  - 로그인 완료 후 원래 접근하려던 참가 신청 페이지로 자동 복귀합니다.

## 3. 사용자 인터랙션 및 UX 흐름 (Step-by-Step)

1. **비회원 접근 제어**:
   - 비회원이 카카오톡 등 단톡방에 공유된 링크를 클릭하여 접속하면, 본문이 렌더링되기 전에 `/auth/login?redirect=/gigs/:id/join`으로 즉시 튕깁니다.
   - 로그인이 완료되면 즉시 본 페이지로 되돌아옵니다.
2. **공연 및 선곡회의 일정 확인**:
   - 상단 카드에서 공연 타이틀, 포스터, 공연 일시뿐만 아니라 **선곡회의 일시**와 공연 장소를 확인합니다.
3. **참여 여부 선택**:
   - **참여 (Going)**: "무대 세션으로 참여합니다." 선택 시 희망 세션 파트(드롭다운/직접입력) 및 전달 메모 입력란이 노출됩니다.
   - **불참 (Not Going)**: "이번 공연은 참석이 어렵습니다." 선택 시 사유 메모(선택) 입력란이 제공됩니다.
   - **미정 (Undecided)**: "일정을 조율하고 있습니다." 선택 시 사유 메모(선택) 입력란이 제공됩니다.
4. **신청 제출 및 수정 (`submitGigRsvp` Action)**:
   - `[참가 여부 제출하기]` 버튼 클릭 시 로딩 스피너 활성화 (`pending === true`).
   - `gig_rsvps` 테이블에 `(gig_id, user_id)` Unique 기준으로 레코드가 UPSERT됩니다.
   - 제출 완료 시 상단 토스트 알림(`참가 신청이 완료되었습니다!`)이 노출되고, 이후 페이지 재방문 시 본인이 제출했던 상태/파트/메모가 그대로 복원되어 자유롭게 수정할 수 있습니다.
5. **관리자 확인 연동**:
   - 회원이 제출한 내역은 공연 상세 페이지(`/gigs/:id`)의 관리자 전용 **[참가 신청 현황]** 섹션에 실시간 집계(참여 N명, 불참 N명, 미정 N명)되어 명단 테이블에 노출됩니다.
6. **페이지 이탈 방지 확인 팝업 (`LeaveConfirmDialog` 및 `beforeunload`)**:
   - 참가 여부(참여/불참/미정), 희망 세션 파트 또는 메모를 수정한 상태에서 저장하지 않고 상단 내비게이션, 헤더 링크 클릭 또는 브라우저 탭 닫기/새로고침을 시도할 경우 변경사항 유실을 방지하기 위한 확인 팝업("페이지를 벗어나시겠습니까?")을 표시합니다.

## 4. UI 상태 (States)

| 상태 | 화면 표시 및 처리 |
| :--- | :--- |
| **비로그인 (Unauthenticated)** | 서버 사이드에서 로그인 페이지로 즉시 강제 리다이렉트 (정보 은닉) |
| **최초 접속 (First-time)** | 기본 선택 `'going'`, 프로필 파트 자동 주입 |
| **재접속/수정 (Existing RSVP)** | 이전 선택 상태/파트/메모 복원, `[참가 신청 내역 수정하기]` 버튼 |
| **제출 중 (Pending)** | 버튼 비활성화 및 로딩 스피너 작동 |
| **제출 완료 (Success)** | 토스트 알림 및 최신 데이터 반영 |
