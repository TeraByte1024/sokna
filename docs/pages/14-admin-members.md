# 14. 회원(관리자) 관리 (`/admin/members`)

## 접근과 목적

- 관리자 전용. 검증된 Auth 사용자 ID가 `admins.id`에 있을 때만 공통 관리자 레이아웃과 이 화면에 접근한다.
- 승인된 정식 회원 목록에서 회원 정보 및 관리자 권한을 관리한다.
- 가입·공연 신청 승인은 [가입/공연 신청 승인](./15-admin-approvals.md) 화면에서 처리한다.

## 회원 목록

- 기본 목록은 `users.status = 'approved'`이다. 이름·이메일·기수·세션 통합 검색, 기수·세션·관리자 여부 필터는 검색창 옆 chevron 버튼으로 펼치는 영역에 공통 드롭다운 메뉴로 제공한다. 필터 영역은 처음에는 접고, 적용된 필터 수를 버튼에 표시한다.
- 숫자가 작을수록 높은 기수로 취급한다. 기본 기수 높은 순은 숫자 오름차순, 기수 낮은 순은 숫자 내림차순으로 정렬하고 기수 미입력 회원은 마지막에 둔다. 이름순, 최근/오래된 승인순도 공통 드롭다운 메뉴에서 제공한다. 검색 결과 수와 빈 결과 안내를 표시한다.
- 검색·정렬 영역은 표 밖에 배치하고 별도의 관리자 명단이나 상단 인원 수 칩은 표시하지 않는다. 표에는 이름, 기수, 세션, 마케팅 수신 동의 여부를 표시하며 이메일은 데스크톱에서만 표시한다. 관리자 이름 앞에는 왕관 아이콘을 표시한다.
- 행 전체를 클릭하거나 키보드로 선택해 상세 dialog를 연다. 데스크톱 행에는 hover 또는 키보드 포커스 시에만 수정하기 안내를 표시한다. 상세 dialog의 제목은 회원 정보이며, 이름·기수·세션을 본문에 표시하고 닫기는 X 아이콘 버튼으로 제공한다. 상세 dialog에는 이메일, 마케팅 수신 동의 여부, 관리자 임명일, 관리자 임명/해제 및 회원 정보 수정 버튼을 둔다.
- 이름·기수·세션 수정은 `updateMemberByAdminAction`을 사용한다. 수정 dialog의 입력은 회원가입·프로필 화면과 같은 이름·기수·세션 선택 양식을 사용한다. 입력 중 이탈 시 `LeaveConfirmDialog`로 확인한다.

## 관리자 권한

- `admins.id`와 회원 ID를 비교하여 관리자 여부를 표시한다. 이메일은 표시·임명에만 사용한다.
- 승인 회원에게 `grantAdminAction`으로 관리자 권한을 부여하고, 회원 상세 dialog에서 `revokeAdminAction`으로 권한을 회수한다.
- 대상 확인 후 실행한다. 이메일이 없는 회원은 임명할 수 없고, 마지막 관리자 및 본인 권한은 회수할 수 없다.

## 화면 상태와 데이터

- 명단 조회 오류, 필터 결과 없음, 권한 처리 오류를 각각 표시한다. 처리 중 중복 실행을 막는다.
- 두 dialog와 이탈 확인 dialog는 문서 최상위에 렌더링하여 배경이 뷰포트 전체를 덮고, 좁은 화면에서는 내용이 스크롤된다.
- 좁은 화면에서는 이메일 컬럼을 숨기고 각 행을 한 줄로 유지한다. 이름은 5글자를 넘으면 말줄임표로 줄이고, 행의 이동 표시는 유지한다. 공통 관리자 메뉴·제목·표 스타일을 사용한다.
- 화면: `app/admin/members/page.tsx`, `member-management-client.tsx`. 액션: `app/admin/members/actions.ts`.
