# 15. 가입/공연 신청 승인 (`/admin/approvals`)

## 접근과 화면

- 관리자 전용. 공통 관리자 메뉴에서 진입하며 `/admin`은 이 화면으로 이동한다.
- 가입 신청과 공연 참가 신청을 별도 표로 표시한다. 각 표는 대기 건수와 빈 목록·조회 실패 안내를 제공한다. 데스크톱에서는 표의 처리 버튼을 사용하고, 모바일에서는 좌우 여백과 행 높이를 확보한 한 줄짜리 신청 표의 행을 눌러 상세 처리 dialog를 연다. 행은 hover·터치·키보드 포커스 배경과 오른쪽 이동 표시로 선택 가능함을 알린다. 이름 컬럼은 5글자 너비에서 말줄임표로 줄인다. 모바일 가입 신청 표에는 이름·기수·세션·신청 경과를 표시하고 이메일·정확한 신청일시는 dialog에서만 표시한다. 공연 신청 표에도 신청 경과를 표시한다.
- 가입 신청은 프로필을 완성한 대기 회원만 표시한다. 이름·기수·세션·이메일·신청일시를 검토하고 정보 수정, 승인, 반려가 가능하다.
- 공연 신청은 `status = going` 및 `review_status = pending`이면서 아직 해당 공연의 `performers`에 없는 건만 표시한다. 공연·신청자·기수·희망 세션·비고·신청일시를 확인하고 승인 또는 반려한다.

- 데스크톱·모바일 표의 경과 시간 컬럼은 시각적 헤더 문구 없이 방금 전·N분 전·N시간 전·N일 전으로 표시하고 1분마다 갱신한다. 정확한 신청일시는 마우스 오버 시와 모바일 처리 dialog에 연·월·일·시·분을 한국 시간대(Asia/Seoul)로 표시한다. 가입 신청은 `users.applied_at`, 공연 참가 신청은 현재 대기 요청의 `gig_rsvps.updated_at`을 사용한다.

## 데이터 흐름

- 가입 승인: `approveMemberAction` → `approve_member_with_notification`. 가입 반려: `rejectMemberAction`으로 현재 `pending` 행만 갱신한다.
- 공연 승인·반려: `reviewGigRsvp(gigId, rsvpId, updatedAt, decision)` → `review_gig_rsvp` RPC. 행 잠금과 `updated_at` 비교로 중복·오래된 처리를 막는다.
- 승인 시 `performers` 등록과 RSVP `approved` 기록을 같은 트랜잭션에 저장한다. 반려 시 RSVP를 삭제하지 않고 `rejected`, 처리자, 처리 시각을 저장한다.
- 반려된 회원은 공연 신청을 다시 저장해 `pending`으로 재신청할 수 있다. 새 전환에 한 번만 관리자 알림을 생성한다.
- 처리 후 승인 화면, 공연 관리 화면, 관련 공연 상세·수정·선곡회의 캐시를 갱신한다.

## 상태와 예외

- 수정·승인·반려 버튼에는 각 동작을 나타내는 아이콘과 넉넉한 클릭 영역을 제공한다. 승인·반려는 채워진 강조 버튼으로, 수정은 보조 버튼으로 표시한다. 승인 버튼은 초록색 배경과 흰색 체크 아이콘·텍스트로 표시한다. 반려 버튼에는 원 테두리가 없는 엑스 아이콘을 사용한다.
- 모바일 처리 dialog에는 가입 신청의 이름·기수·세션·이메일·신청일시, 공연 신청의 공연·신청자·기수·희망 세션·비고·신청일시를 표시하고 데스크톱과 같은 아이콘을 사용하는 수정·승인·반려 버튼을 제공한다.
- 가입·공연 참가 신청의 승인 및 반려 전에 대상자와 공연명을 포함한 확인 창을 표시한다. 처리 중에는 중복 제출을 막고, 성공·실패 결과는 알림으로 안내한다.
- 신청이 변경되거나 이미 처리된 경우 최신 내역을 다시 확인하도록 안내한다.
- 회원 정보 수정 중 이탈하면 기존 `LeaveConfirmDialog`로 경고한다.
