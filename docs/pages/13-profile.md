# 13. 회원 정보 수정 페이지 (`/profile`) [로그인 회원 전용]

## 1. 개요 및 접근 권한
- **URL 경로**: `/profile`
- **대상 사용자**: **로그인한 동아리 회원 전용**
- **목적**: 본인의 회원 정보(이름, 기수, 담당 세션 파트, 행사 소식 수신 동의)를 확인 및 수정.
- **보안 및 권한 정책**:
  - 비로그인 사용자는 `/auth/login?redirect=/profile`로 자동 리다이렉트.
  - 소셜 로그인 후 기수·세션 등록을 완료하지 않은 미신청 계정은 `/auth/complete-profile`로 안내합니다. 이미 승인된 회원과 관리자는 기존 프로필 화면을 사용합니다.

---

## 2. 디자인 및 화면 레이아웃 (Layout & Visuals)

- 계정 기본 정보 카드: 가입 이메일, 승인 상태, 가입 신청일, 승인일. 카드 하단 오른쪽에 아이콘과 텍스트가 있는 `[로그아웃]` 버튼을 표시하며, 모바일과 데스크톱에서 모두 사용할 수 있습니다.
- 회원 정보 수정 폼:
  - 이름(실명) 입력 필드.
  - 기수(숫자) 입력 필드.
  - 이메일·기수·세션은 `라벨 → 설명 → 입력/선택` 순서로 세로 배치합니다. 라벨과 설명 사이 4px, 설명과 입력/선택 사이 8px 간격을 유지합니다. 설명은 `FieldDescription`의 11px·여유 있는 줄 간격(`leading-relaxed`)·보조 색상(`text-muted-foreground`)을 공통 적용하고 `aria-describedby`로 해당 필드와 연결합니다. 수신 동의와 기기 상태 설명에도 같은 스타일을 적용하며, 동의 시각 상태 표시는 유지합니다.
  - 담당 세션(파트)은 회원가입·소셜 가입과 같은 `MemberSessionField` 컴포넌트를 사용합니다. 프리셋은 `보컬(남)`, `보컬(여)`, `기타`, `베이스`, `드럼`, `건반`, `창작`, `직접 입력`이며, 직접 입력을 선택하면 세션명 입력란을 표시합니다.
  - 공연/행사 및 앱 푸시 알림 수신 동의 체크박스. 기존 상태 칩 대신 라벨 다음 줄에 `YYYY. MM. DD. HH:mm 동의함`(한국 시간)을 표시합니다. 동의 시각이 null인 기존 동의자는 `동의함`만 표시하고, 미동의자는 `미동의`로 표시합니다.
  - 바로 아래 `이 기기에서 알림 받기` 토글: 벨 아이콘과 문구를 한 줄에 놓고 오른쪽에 스위치를 표시합니다. 현재 계정의 서버 등록·수신 동의와 실제 브라우저 FCM 토큰·권한을 검증한 뒤 ON으로 표시하며 확인 중에는 비활성화합니다. 지원하지 않거나 권한이 거부된 브라우저에서는 비활성화하고 이유를 안내합니다. 계정 전환 또는 서버 등록 삭제 시 이전 ON 표시를 유지하지 않습니다.
  - 카드 하단의 같은 행에서 왼쪽에 `[회원 탈퇴하기]`, 오른쪽에 `[변경사항 저장하기]` 버튼을 배치합니다. 높이는 40px로 맞추고 최소 가로 32px 간격을 두며, 좁은 화면에서 줄바꿈되면 세로 24px 간격을 유지합니다.
- 탈퇴 관련 안내와 확인 입력은 `[회원 탈퇴하기]` 버튼 클릭 후 열리는 다이얼로그에 표시합니다.

## 3. 사용자 인터랙션 및 UX 흐름

1. **정보 조회 및 폼 초기화**:
   - `users` 테이블에서 현재 로그인 사용자의 정보를 불러와 기본값으로 바인딩.
   - 저장된 `보컬(남)`·`보컬(여)` 등 프리셋은 해당 버튼을 선택합니다. 기존 `보컬`이나 그 밖의 사용자 입력 값은 `직접 입력`으로 표시하여 원래 내용을 보존합니다.
2. **정보 수정 및 저장 (`updateMyProfileAction`)**:
   - 이름, 기수, 파트, 수신 동의 여부를 변경하고 `[변경사항 저장하기]` 클릭 시 DB에 반영 및 토스트 알림 표시.
   - 프로필의 세션은 선택 사항입니다. 선택된 버튼을 다시 누르면 해제되며, 미선택 또는 빈 직접 입력 값은 `null`로 저장합니다. 직접 입력 값의 앞뒤 공백은 제거합니다.
   - 수신 동의를 저장한 뒤 프로필의 기기 토글 또는 데스크톱 헤더 프로필 메뉴에서 브라우저 권한을 허용하고 FCM 토큰을 등록할 수 있습니다. 아직 동의하지 않았다면 토글을 켤 때 기존 수신 동의 다이얼로그를 먼저 표시합니다.
   - 수신 동의를 끄고 저장하면 공통 동의 저장 함수와 DB 트리거가 동의 변경·시각 초기화·모든 기기 토큰 삭제를 하나의 트랜잭션으로 처리합니다. 삭제 실패 시 동의 변경도 롤백됩니다. 현재 브라우저의 후속 해제는 이미 삭제된 서버 등록도 정상 처리하여 로컬 토큰 정리를 완료합니다. 동의 값이 누락된 저장 요청은 거절합니다.
   - 동의 시각은 DB 트리거가 `false → true` 전환에 기록하며 재동의 시 갱신합니다. 기존 동의자의 null 값은 소급 기록하지 않습니다.
   - 기기 토글은 다시 눌러 끌 수 있습니다. 끄면 현재 브라우저의 토큰만 해제하며 전체 수신 동의와 동의 시각은 유지합니다. 헤더 메뉴와 프로필의 기기 상태는 같은 토큰 변경 이벤트로 동기화합니다.
   - 로그아웃은 기기 등록을 유지하고 수신 계정 연결만 정지합니다. 다른 사용자가 로그인하면 동일 기기를 그 사용자에게 연결하고 새 계정의 수신 동의에 따라 ON/OFF를 결정합니다. 이전 계정의 알림은 표시하거나 클릭해 이동할 수 없습니다. 기존 등록의 안전한 이전 조건은 [웹 푸시 알림 명세](../features/push-notifications.md#23-기기-등록과-로그인-계정-연결)를 따릅니다.
3. **페이지 이탈 방지 확인 팝업 (`LeaveConfirmDialog` 및 `beforeunload`)**:
   - 폼 작성 및 수정 중(`isDirty`) 사용자가 상단 네비게이션, 헤더 링크 클릭 또는 브라우저 탭 닫기/새로고침을 시도할 경우 변경사항 유실을 방지하기 위한 확인 팝업("페이지를 벗어나시겠습니까?")을 표시합니다.
   - 저장 완료 시에는 정상 제출 플래그(`markSubmitting()`)를 통해 팝업 없이 즉시 최신 상태가 반영됩니다.
4. **로그아웃**:
   - 상단 요약 카드의 `[로그아웃]` 버튼으로 현재 기기에서 로그아웃하고 로그인 화면으로 이동합니다. 기기 등록을 유지하고 현재 계정의 수신 연결만 정지하는 공통 `signOutWithPushSession()`을 사용합니다.
   - 미저장 변경이 있으면 기존 이탈 확인 다이얼로그를 먼저 표시합니다. 취소하면 편집과 로그인을 유지하고, 확인하면 로그아웃합니다. 실패하면 오류를 안내하고 미저장 변경 경고를 복구합니다.
   - 저장·탈퇴·푸시 설정 중에는 로그아웃을 비활성화하며, 로그아웃 중에는 폼 입력과 저장·탈퇴·푸시 설정을 비활성화합니다.
5. **회원 탈퇴 (`deleteMyAccountAction`)**:
   - 수정 카드 하단 왼쪽의 `[회원 탈퇴하기]` 버튼으로 다이얼로그를 엽니다. 다이얼로그 안에서 안내를 확인하고 `탈퇴`를 정확히 입력한 뒤 최종 제출하거나 취소할 수 있습니다.
   - 다이얼로그 안에서 계정과 개인 알림·신청 정보는 삭제되며, 공연·선곡 등 공유 기록은 남을 수 있고 복구할 수 없음을 안내합니다.
   - 프로필 저장·푸시 설정과 탈퇴 처리를 동시에 실행할 수 없습니다. 실패 시 확인 창에 오류를 표시하고 다시 시도할 수 있습니다.
   - 마지막 관리자는 다른 관리자를 지정한 뒤 탈퇴해야 합니다.
   - 성공하면 `회원 탈퇴가 완료되었습니다.` 브라우저 알림을 표시합니다. 사용자가 확인하면 미저장 변경 경고를 해제하고 로컬 세션·기기 토큰을 정리한 뒤 홈으로 이동합니다.
   - 상세 데이터 처리 규칙: [회원 탈퇴 명세](../features/account-withdrawal.md).
