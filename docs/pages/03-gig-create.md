# 03. 공연 등록 페이지 (`/gigs/new`) [관리자 전용]

## 1. 개요 및 접근 권한
- **URL 경로**: `/gigs/new`
- **대상 사용자**: **관리자(Admin) 전용**
- **목적**: 새로운 공연 일정을 생성하고, 해당 무대에 참가할 동아리 회원들을 검색하여 세션 참여자(Performer)로 등록 및 파트 지정.

---

## 3. 사용자 인터랙션 및 UX 흐름 (Step-by-Step)

1. **권한 인가 검사 (Access Control)**:
   - 비관리자 또는 비로그인 사용자가 직접 URL로 접근할 경우, 폼 대신 **접근 제한 카드**가 렌더링됩니다:
     - 문구: `"공연 추가는 관리자 권한이 필요합니다."`
     - 버튼: `[로그인]` (`/auth/login`), `[목록으로]` (`/gigs`)
2. **공연 기본 정보 작성**:
   - 공연 제목(필수), 공연 일시(필수), 곡 선정 회의 일시(선택)를 입력합니다.
3. **참여자 검색 및 배정 (Performer Selection)**:
   - 검색창에 2글자 이상 입력 시 300ms 디바운스를 거쳐 `public.users` 테이블에서 이름/이메일 일치 사용자를 조회합니다.
   - 검색 결과 드롭다운에서 멤버를 클릭하면 참여자 칩 리스트에 즉시 추가됩니다.
   - 잘못 추가한 경우 칩 우측의 `[X]` 버튼을 눌러 제거할 수 있습니다.
4. **저장 및 제출 (`createGig` Action)**:
   - `[공연 등록]` 버튼 클릭 시 로딩 스피너 활성화 (`pending === true`).
   - 서버 사이드에서 `gigs` 테이블에 insert 후 생성된 `gig.id`를 기반으로 `performers` 테이블에 N:M 매핑 데이터를 일괄 insert합니다.
   - 성공 시 `/gigs` 목록 페이지로 리다이렉트되고 새 공연이 즉시 반영됩니다.

---

## 4. UI 상태 (States)

| 상태 | 화면 표시 및 처리 |
| :--- | :--- |
| **비인가 상태 (Non-admin)** | `접근 제한` 카드 표시 (폼 노출 안 됨) |
| **작성 중 (Normal)** | 입력 필드 활성화 및 유저 검색 드롭다운 |
| **제출 중 (Pending)** | 제출 버튼 비활성화 및 로딩 스피너 작동 |
| **검증 실패 (Validation)** | 에러 메시지 표시 (예: `"공연 제목은 필수입니다."`) |
