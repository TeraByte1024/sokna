# 01. 메인 랜딩 페이지 (`/`)

## 1. 개요 및 접근 권한

- **URL 경로**: `/`
- **대상 사용자**: 모든 사용자(방문자, 일반 회원, 관리자)
- **현재 상태**: 정식 소개 콘텐츠 제작 전 임시 랜딩 페이지
- **목적**: 사이트가 개발 중임을 명확히 안내하면서 사용 가능한 공연 정보와 로그인 화면으로 연결합니다.

---

## 2. 현재 임시 화면 구성

```text
+-------------------------------------------------------------------+
| 데스크톱: [SOKNA Logo] [공연]                     [계정/로그인] |
+-------------------------------------------------------------------+
|                                                                   |
| [IN PROGRESS]                    +-----------------------------+  |
| SOKNA · Since 1986               | 이 페이지는                 |  |
| 소리로 크는 나무                  | 개발 초기 단계 안내          |  |
| 한양대 X 한양여대 연합 밴드동아리 | 공연 정보 / 선곡 회의        |  |
| [공연 둘러보기] [회원 로그인]※   | 중요 알림 / 활동 기록        |  |
|                                   +-----------------------------+  |
|                                                                   |
+-------------------------------------------------------------------+
```

※ `회원 로그인` 버튼은 비로그인 상태에서만 표시합니다.

### 2.1 히어로 안내

- `IN PROGRESS` 상태 배지와 공사 중 아이콘, 기존 동아리 이름과 소개 문구를 표시합니다.
- 배경은 외부 이미지 없이 그리드 패턴과 violet/sky 계열의 은은한 블러 효과로 구성합니다.
- 모바일에서는 소개 문구를 왼쪽 정렬하고, 비로그인 상태의 버튼 두 개를 나란히 배치합니다. 상태 카드는 소개 아래에 놓고 설명을 줄이지 않고 모두 표시합니다. 태블릿·데스크톱에서는 기존 반응형 배치를 유지합니다.

### 2.2 주요 이동 버튼

- `[공연 둘러보기]`: `/gigs`로 이동합니다.
- `[회원 로그인]`: 비로그인 상태에서만 표시하며 `/auth/login`으로 이동합니다. 로그인 상태는 서버에서 현재 Supabase 세션의 claims로 확인합니다. 로그인한 회원에게는 `[공연 둘러보기]` 버튼만 표시합니다.
- 공통 `SiteLayout`을 사용합니다. 모바일 헤더에는 로고와 기존 계정/로그인 동작을 유지하고, 주요 메뉴는 화면 하단의 `홈`(`/`), `공연`(`/gigs`), `프로필`(`/profile`)로 표시합니다. 비로그인 사용자가 프로필을 누르면 기존 인증 흐름에 따라 로그인 화면으로 이동합니다.
- 하단 내비게이션은 현재 경로를 강조하고 기기 안전 영역을 고려합니다. 본문과 푸터 아래에 내비게이션 높이만큼 여백을 두어 콘텐츠가 가려지지 않게 합니다. 데스크톱에서는 기존 상단 공연 메뉴를 사용합니다.

### 2.3 개발 상태 카드

- 모바일에서는 소개 아래, 데스크톱에서는 우측 카드에 정적인 개발 상태 안내와 다음 항목을 표시합니다.
  - 공연 정보
  - 선곡 회의
  - 중요 알림
  - 활동 기록
- 화면 진입 시에만 짧은 페이드 애니메이션을 사용하며 반복 애니메이션은 표시하지 않습니다.

---

## 3. 향후 전환 원칙

- 동아리 소개, 활동 사진 및 정식 홍보 콘텐츠가 확정되면 현재 임시 랜딩을 정식 랜딩으로 교체합니다.
- 공연 및 인증 기능의 경로는 정식 랜딩에서도 유지합니다.
- 정식 콘텐츠 적용 전까지 외부 임시 이미지에 의존하지 않습니다.
