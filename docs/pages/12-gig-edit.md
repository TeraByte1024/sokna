# 12. 공연 수정 기능 (`/admin/gigs/:id`) [관리자 전용]

> 2026-10-05: 기본 정보·SETLIST·공연자 명단 수정 기능을 관리자 공연별 페이지로 통합했다. 기존 `/gigs/:id/edit`는 권한 확인 후 `/admin/gigs/:id#gig-basic-info`로 이동한다. 아래 폼 기능 명세는 통합 페이지에서도 동일하게 적용한다.

## 1. 개요 및 접근 권한
- **URL 경로**: `/admin/gigs/:id` (기존 `/gigs/:id/edit`는 호환 리다이렉트)
- **대상 사용자**: **관리자(Admin) 전용**
- **목적**: 기 등록된 공연의 기본 정보(제목, 일정, 선곡회의, 장소, 포스터, 공개 여부) 및 참여 세션원 명단을 수정하고 DB와 동기화.
- **로딩 상태**: 공연 추가 페이지와 같은 공통 폼 스켈레톤(뒤로가기·제목·기본 정보의 포스터/입력칸)을 표시합니다. 스크린리더에는 로딩 문구를 알리고 움직임 줄이기 설정 시 점멸을 멈춥니다.
- **조회 순서**: 관리자 권한 확인 후 공연 기본 정보는 요청 단위로 재사용하고, 공연자·확정 셋리스트는 병렬 조회합니다. 공연자·셋리스트 조회 실패 시 오류를 표시하고 수정 폼을 렌더링하지 않습니다.
- **통합 페이지**: 메뉴와 본문은 기본 정보·선곡회의 곡 목록·SETLIST 관리·공연자 관리·공연자별 곡 응답 현황 순서입니다. 기본 정보와 SETLIST 사이에 읽기 전용 후보곡 목록을 표시하고, 기존 3개 수정 섹션은 한 폼에서 저장합니다. 중복된 폼 제목과 뒤로가기 링크는 생략합니다. 상단 5개 바로가기로 각 섹션에 이동합니다. 저장 후 같은 관리자 공연 페이지를 다시 조회하고 취소는 관리자 공연 목록으로 이동합니다. 기존 변경사항 이탈 확인을 유지합니다.

## 3. 사용자 인터랙션 및 UX 흐름

1. **권한 인가 검사 (Access Control)**:
   - 관리자 레이아웃과 서버 데이터 로더(`GigEditSection`)에서 `getIsAdmin()`을 호출하여 검증. 기존 수정 URL도 리다이렉트 전에 동일한 권한 검사를 적용.
   - 비관리자 또는 비회원 접속 시 `/gigs/:id`로 즉시 리다이렉트 처리.
   - **셋리스트 수정/삭제 권한**: 공연 정보에 포함된 셋리스트(`order_num > 0`)의 수정 및 삭제는 **오직 관리자(Admin) 전용**이며, 곡 등록자 본인이라 하더라도 공연 정보에서는 수정/삭제 권한이 없습니다 (선곡 회의 후보곡에서만 본인 삭제/수정 가능).

2. **기존 데이터 바인딩**:
   - `gigs` 테이블에서 공연 기본 정보를 fetch하여 제목, 부제목, 공연 일시(일자 및 24h 시각), 선곡회의 일시(일자 및 24h 시각), 추천곡 접수 마감 기한, 공연 장소, 선곡회의 장소, 포스터 URL, 공개 여부 상태에 기본값으로 자동 바인딩. 일시 필드는 데스크톱에서 날짜(2/3)와 시각(1/3)이 1행으로 배치됩니다. 모바일에서는 페이지 좌우 패딩을 줄이고 시각 입력에 필요한 폭을 확보하며, 390px 미만 화면에서는 날짜와 시각을 세로로 배치해 브라우저 기본 입력 버튼이 잘리지 않게 합니다.
   - `performers`와 `users` 테이블을 조인 조회하여 기존 참여자 목록(연동 회원 및 미연동 더미 공연자 포함)을 테이블에 복원.
3. **3개 섹션 카드 분리 및 정보 수정**:
   - 기존의 단일 카드 내 모든 요소가 들어가 있던 구조를 독립된 3개 섹션 카드(`기본 정보` / `SETLIST 관리` / `공연자 관리`)로 분리하여 레이아웃 계층을 명확히 정돈했습니다.
   - **1. 기본 정보 (Basic Info)**:
      - **포스터 & 제목/부제목 레이아웃**: 공연 상세 페이지와 동일하게 좌측에 포스터(규격 1:1.41), 우측에 공연 제목 및 공연 부제목을 나란히 배치(`포스터 | 제목`, `포스터 | 부제목`).
      - **사전예매 / 현장예매 가격 입력**: 공연 부제목 하단에 2열 그리드로 사전예매 가격(`advance_ticket_price`) 및 현장예매 가격(`door_ticket_price`) 입력 텍스트 필드를 제공하며, 입력 시 천 단위 구분 콤마가 실시간 포맷팅되고 원화(KRW, 정수) 단위로 저장됩니다.
      - **포스터 이미지 등록/수정**: 기존 포스터를 교체하거나 삭제 가능하며, 표준 A-규격(1:1.41) 비율 미리보기와 이미지 파일 **드래그 앤 드롭(Drag & Drop)** 업로드를 지원합니다.
      - **공연/선곡회의 일시 및 장소**: 일시는 날짜와 24h 시각 1행 배치, 장소와 너비 정렬 통일. 변경사항 감지는 공연·선곡회의 시각과 선곡회의 장소 변경도 포함합니다.
      - **추천곡 접수 마감 기한**: 선곡회의 일시 아래 날짜(2/3)와 시간(1/3) 입력을 수정 화면에서만 제공합니다. 두 값을 모두 비워 저장하면 마감 기한이 없습니다. 다른 입력 및 섹션 구성은 유지합니다.
      - **공개 범위**: `비공개`(관리자만) / `회원 공개`(로그인 회원) / `전체 공개`(모든 방문자) 선택 가능. 기존 비공개(`is_public=false`)는 회원 공개로 복원합니다.
   - **2. SETLIST 관리 (총 n곡)**:
       - **섹션 제목 및 조작 버튼 통합**: CardHeader에 `SETLIST 관리 (총 n곡)` 제목과 3개의 조작 버튼(`[세션 순서 설정]`, `[선곡회의 곡 가져오기]`, `[엑셀에서 공연자 / 셋리스트 불러오기]`)을 배치하여 조작성을 극대화했습니다.
       - **세션 표시 순서 일괄 및 개별 편집**:
         - **전체 세션 순서 설정 (`SessionOrderDialog`)**: `[세션 순서 설정]` 버튼을 통해 모달 다이얼로그를 열고, 셋리스트 내 모든 곡에 표시되는 세션 종류(보컬, 기타, 베이스, 건반, 드럼 등)의 표시 순서를 상하 이동 버튼이나 빠른 프리셋(기본 밴드 순서: 보컬 우선, 리듬 섹션 우선: 드럼/베이스 우선, 가나다순)으로 일괄 편집하여 모든 곡에 동시 적용할 수 있습니다. 커스텀 세션 종류 추가 및 미사용 세션 제거도 지원합니다.
         - **곡별 인라인 세션 좌우 이동**: 각 곡의 세션 칩 좌측에 미니 좌우 이동 버튼(`<`/`>`)을 제공하여, 특정 곡 내에서만 세션 슬롯 순서를 즉시 맞바꿀 수 있습니다.
      - **인라인 세션 칩 & 확장 입력 / 세션 삭제 확인**: 불필요한 '세션 및 연주자 구성:' 레이블을 제거하고 수평 인라인 칩(`[세션명 | 이름 ✕ ... | + | 🗑]`)으로 구성됩니다. 각 세션의 인원 추가는 평소 콤팩트한 `+` 버튼으로 접혀 있다가 클릭 시 텍스트 필드로 확장되어 부원 자동완성 검색 및 직접 입력을 지원합니다. 또한 `[+ 세션 추가]` 버튼 역시 클릭 시 인라인 텍스트 필드로 확장되어 새 세션명을 입력하여 바로 추가할 수 있습니다(세션 추가 시 불필요한 토스트 미노출, 자주 쓰는 세션 드롭다운 폐기). 세션 칩의 `🗑` 삭제 버튼 클릭 시 확인 다이얼로그(배정 인원 안내 및 삭제 확인)를 표시하여 오동작을 방지합니다.
      - **셋리스트 정보의 비연동(텍스트) 원칙**: 셋리스트의 세션 연주자 정보는 실제 회원 계정 연동이나 더미 공연자 생성 없이, 입력된 이름을 텍스트 형태로만 `session_members`에 저장하여 LINEUP(공연자 명단)과의 의존성을 분리합니다.
      - **선곡회의 곡 가져오기 (Nomination Import)**: `[선곡회의 곡 가져오기]` 버튼을 통해 해당 공연의 선곡회의 후보곡(`nominations`) 목록을 모달 다이얼로그로 확인하고, 원하는 곡들을 다중 선택하여 실제 셋리스트에 텍스트 형태로 자동 복사/추가할 수 있습니다. (추천 보컬이 있는 경우 보컬 슬롯에 자동 배정)
      - **엑셀에서 공연자 / 셋리스트 불러오기 (스마트 Conflict 해결)**: 엑셀 표를 복사/붙여넣기하여 공연자와 셋리스트를 일괄 파싱하고, 등록 회원 세션 불일치(1단계)·비인명 감지·중복 이름·계정 매칭·보컬 성별 등 5단계 Conflict 해결 및 부원 자동 연동 후 기존 내역을 안전하게 덮어쓰기(Replace) 등록합니다.
   - **3. 공연자 관리 (총 n명)**:
      - **공연 참여자 표**: 번호, 이름, 기수, 세션, 비고, 연동 상태, 삭제 컬럼을 표시합니다. 비고는 같은 공연의 신청 `gig_rsvps.note`를 회원 ID로 연결해 읽기 전용으로 표시하며, 선곡회의 응답 메모와 같은 메시지 아이콘·연한 배경·둥근 테두리 칩을 사용합니다. 긴 내용은 말줄임하며 툴팁으로 전체 내용을 확인합니다. 미작성·미연동은 `-`, 조회 실패는 `조회 실패`로 표시합니다.
      - **다양한 정렬 지원 (기본: 이름 > 기수)**: 기본값으로 이름 가나다순 및 동일 이름 시 기수 오름차순으로 정렬되며, 테이블 헤더(`이름`, `기수`, `#`) 클릭 및 툴바의 정렬 드롭다운 메뉴(`[이름순 (이름 > 기수)]`, `[기수순 (기수 > 이름)]`, `[등록순]`)를 통해 언제든 원하는 순서로 정렬할 수 있습니다.
      - **스마트 자동 매핑**: 엑셀 명단 일괄 붙여넣기 및 셋리스트 가져오기 시 `users` 테이블을 조회하여 고유한 회원이 존재할 경우 자동으로 회원 계정과 매핑합니다.
      - **미연동 더미 보존 & 수동 매핑**: 계정과 연동되지 않은 공연자도 DB에 더미 레코드(`user_id = null, name = '...'`)로 보존되며, 미연동 행의 `[🔗 연동]` 버튼으로 실제 부원 계정에 연결할 수 있습니다. 이미 연동된 참여자는 `연동됨` 상태만 표시하고 연동 변경·해제 버튼을 제공하지 않습니다.
      - **더미 공연자 직접 추가**: 이름과 세션을 입력해 미연동 공연자를 한 명씩 명단에 추가할 수 있습니다. 동일 이름의 미연동 공연자는 중복 추가하지 않습니다.
      - **회원 연동 시 행 덮어쓰기**: 기존 더미 행의 `performers.id`를 유지하며 회원 ID·이름을 갱신합니다. 대상 회원이 이미 명단에 있으면 두 행의 세션을 합쳐 한 행만 남기고, 셋리스트의 이전 이름도 갱신합니다.
      - **건반 명칭 통일 및 중복 제거**: 기존 건반 세션 표기를 `건반`으로 정규화하고, 같은 공연·회원 계정의 중복 행은 파트를 합쳐 한 명으로 표시합니다.
      - **다중 세션 뱃지 지원**: 공연자 1명당 여러 세션을 지정할 수 있으며(`[보컬 ✕] [기타 ✕]`), 기존 `+` 아이콘의 `[+ 추가]` 칩을 클릭하면 그 위치에 텍스트 필드가 나타나 자동 포커스됩니다. 추천 보컬 선택기의 검색창·플로팅 팝업을 참고하고, 바깥 세션 칩과 추가 칩의 디자인을 통일합니다. 입력창과 팝업은 모두 테이블 밖의 포털에 고정 위치로 표시하며 셀에는 원래 추가 칩의 크기만 유지하여 컬럼 폭에 영향을 주지 않습니다. 스크롤·화면 크기·모바일 키보드 변화 시 위치를 갱신합니다.
      - **검색 결과 및 조작**: 팝업 항목은 칩이 아닌 기존 드롭다운의 일반 텍스트 행 서식을 유지합니다. 보컬(남), 보컬(여), 기타, 베이스, 드럼, 건반을 이름 및 동의어로 검색합니다. 이미 배정된 세션도 숨기지 않고 체크 표시·비활성 상태로 보여 중복 추가를 막습니다. 결과 선택 또는 직접 입력 항목 선택으로 추가하며 방향키·Enter 선택, Escape·바깥 클릭·포커스 이탈로 닫기를 지원합니다. 한글 조합 중 Enter는 추가하지 않고 쉼표 입력 및 중복 추가를 차단합니다.
      - **검색 제안 범위**: 이 공연자 행 팝업의 제안 목록에서만 일렉기타, 어쿠스틱기타, 신디사이저, 브라스, 색소폰, 코러스를 제외합니다. 해당 이름을 직접 입력하는 기능이나 다른 화면의 목록은 제한하지 않습니다. 일렉기타·어쿠스틱기타는 기타, 피아노·신디사이저·브라스는 건반 검색 결과로 연결하며 공연 폼의 연주자 추천에서도 기타·건반 계열로 인식합니다.
4. **저장 및 데이터 무결성 보존 (`updateGig` Server Action)**:
   - 선곡회의 후보곡(`nominations.created_by`) 및 참여자 외래키 제약조건을 보호하기 위해 지능형 Diff 동기화 적용:
     - 수정 폼은 기존 `performers.id`를 전송합니다. 서버는 이 ID로 동일 공연의 행을 우선 찾아 `user_id`, 이름, 파트, 사진을 갱신합니다. ID가 없을 때만 회원 ID 또는 더미 이름으로 기존 행을 찾습니다.
     - 동일 회원 ID가 중복 전송되면 저장을 거부합니다. 연동으로 합쳐져 제외된 기존 행의 선곡·셋리스트 등록 기록(`nominations.created_by`, `setlists.created_by`)은 살아남는 행으로 이전한 뒤 삭제합니다. 일반 삭제는 해당 값을 null로 변경합니다.
     - 신규 참여자(연동 및 더미)는 insert하며, 공연자 조회·수정·추가·삭제 오류는 저장 실패로 반환합니다.
   - 셋리스트 목록 또한 곡명, 아티스트, `session_members`(JSON 포맷), `order_num`을 동기화하여 DB에 일괄 갱신.
   - 수정 완료 시 토스트 알림(중복 방지 ID 적용)을 단 1회 띄우고 `/admin/gigs/:id`를 다시 조회하여 최신 응답 현황·공연 정보·명단을 표시.
5. **페이지 이탈 방지 확인 팝업 (`LeaveConfirmModal` 및 `beforeunload`)**:
   - 공연자 삭제는 데스크톱 버튼과 상세 대화상자 모두 확인 대화상자를 거쳐 폼에서 제외합니다. 취소하면 명단을 유지합니다. 모바일 표는 이름·기수·세션을 표시하고 인라인 세션 추가/삭제·연동/삭제 버튼을 생략하며, 행 클릭으로 정보 조회·세션 편집·미연동 계정 연동을 지원합니다. 비고는 있는 경우 아이콘으로 표시하며 전체 내용은 상세 대화상자에서 확인합니다. 자세한 흐름은 [공연 관리](./16-admin-gigs.md)의 모바일 참여자 관리 명세를 따릅니다.
   - 수정 폼 작성 중(`isDirty`) 사용자가 상단 뒤로가기 링크, 하단 [취소] 버튼, 네비게이션 링크를 클릭하거나 브라우저 탭 닫기/새로고침을 시도할 경우, 수정 중이던 내용이 유실되지 않도록 확인 팝업("페이지를 벗어나시겠습니까?")을 표시하여 이탈을 방지합니다.
