# 12. 공연 수정 페이지 (`/gigs/:id/edit`) [관리자 전용]

## 1. 개요 및 접근 권한
- **URL 경로**: `/gigs/:id/edit`
- **대상 사용자**: **관리자(Admin) 전용**
- **목적**: 기 등록된 공연의 기본 정보(제목, 일정, 선곡회의, 장소, 포스터, 공개 여부) 및 참여 세션원 명단을 수정하고 DB와 동기화.

## 3. 사용자 인터랙션 및 UX 흐름

1. **권한 인가 검사 (Access Control)**:
   - 서버 컴포넌트(`GigEditPage`) 레벨에서 `getIsAdmin()`을 호출하여 검증.
   - 비관리자 또는 비회원 접속 시 `/gigs/:id`로 즉시 리다이렉트 처리.
   - **셋리스트 수정/삭제 권한**: 공연 정보에 포함된 셋리스트(`order_num > 0`)의 수정 및 삭제는 **오직 관리자(Admin) 전용**이며, 곡 등록자 본인이라 하더라도 공연 정보에서는 수정/삭제 권한이 없습니다 (선곡 회의 후보곡에서만 본인 삭제/수정 가능).

2. **기존 데이터 바인딩**:
   - `gigs` 테이블에서 공연 기본 정보를 fetch하여 제목, 부제목, 일시(YYYY-MM-DD), 장소, 포스터 URL, 공개 여부 상태에 기본값으로 자동 바인딩.
   - `performers`와 `users` 테이블을 조인 조회하여 기존 참여자 목록(연동 회원 및 미연동 더미 공연자 포함)을 테이블에 복원.
3. **정보 수정 및 파일 관리**:
   - **제목 및 부제목**: 메인 제목과 부제목 입력 필드 제공 (상세 페이지에서 메인 제목 바로 아래 강조 표시).
   - **포스터 변경/삭제**: 기존 포스터를 교체하거나 삭제 가능하며, 표준 A-규격(1:1.41) 비율 미리보기와 이미지 파일 **드래그 앤 드롭(Drag & Drop)** 업로드를 지원합니다.
   - **SETLIST (셋리스트 관리 및 가변 세션)**:
      - **가변 세션 종류 추가/삭제**: 각 곡 카드는 곡번호 | 제목 | 아티스트 | 이동/삭제 버튼이 1행에 배치되며, 하위 세션 영역에서 `[+ 세션 추가]` 버튼을 통해 프리셋 선택 또는 새 세션명 직접 입력을 통해 세션을 추가할 수 있고, 불필요한 세션은 `🗑` 버튼으로 즉시 삭제할 수 있습니다.
      - **배정 인원 전용 뱃지 & 지능형 인원 추가**: 각 세션 상자에는 현재 배정된 인원만 뱃지(`[이름 ✕]`)로 깔끔하게 표시되며, `[+ 인원 추가]` 클릭 시 해당 세션 담당 부원이 상단에 우선 정렬되어 표시됩니다.
      - **엑셀/스프레드시트 일괄 가져오기 (Bulk Import)**: 스프레드시트의 표 영역을 복사하여 붙여넣으면 열을 자동으로 감지하여 세션별로 JSON 구조화된 셋리스트를 일괄 파싱하고 등록합니다.
   - **공연자 관리 및 스마트 연동 / 다중 세션**:
      - **스마트 자동 매핑**: 엑셀 명단 일괄 붙여넣기 및 셋리스트 가져오기 시 `users` 테이블을 조회하여 고유한 회원이 존재할 경우 자동으로 회원 계정과 매핑합니다.
      - **미연동 더미 보존 & 수동 매핑**: 계정과 연동되지 않은 공연자도 DB에 더미 레코드(`user_id = null, name = '...'`)로 온전히 보존되며, 각 행의 `[🔗 연동]` 버튼을 클릭하여 `PerformerMappingDialog`를 통해 언제든 실제 부원 계정으로 매핑 및 변경할 수 있습니다.
      - **다중 세션 뱃지 지원**: 공연자 1명당 여러 세션을 중복 지정할 수 있으며(`[보컬 ✕] [기타 ✕]`), `[+ 추가]` 팝오버를 통해 프리셋 및 직접 입력으로 세션 종류를 자유롭게 추가/삭제 가능합니다.
4. **저장 및 데이터 무결성 보존 (`updateGig` Server Action)**:
   - 셋리스트(`setlists.created_by`) 외래키 제약조건을 보호하기 위해 지능형 Diff 동기화 적용:
     - 기존 참여자는 고유 `performers.id`를 보존하며 파트 및 프로필 사진만 update (더미 공연자가 회원과 연동된 경우 `user_id`를 갱신).
     - 제외 대상 참여자는 등록한 곡이 있을 경우 `setlists.created_by = null` 처리 후 안전 delete.
     - 신규 참여자(연동 및 더미)는 insert.
   - 셋리스트 목록 또한 곡명, 아티스트, `session_members`(JSON 포맷), `order_num`을 동기화하여 DB에 일괄 갱신.
   - 수정 완료 시 토스트 알림(중복 방지 ID 적용)을 단 1회 띄우고 `/gigs/:id`로 자동 복귀.
5. **페이지 이탈 방지 확인 팝업 (`LeaveConfirmModal` 및 `beforeunload`)**:
   - 수정 폼 작성 중(`isDirty`) 사용자가 상단 뒤로가기 링크, 하단 [취소] 버튼, 네비게이션 링크를 클릭하거나 브라우저 탭 닫기/새로고침을 시도할 경우, 수정 중이던 내용이 유실되지 않도록 확인 팝업("페이지를 벗어나시겠습니까?")을 표시하여 이탈을 방지합니다.
