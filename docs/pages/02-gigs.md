# 02. 공연 목록 페이지 (`/gigs`)

## 1. 개요 및 접근 권한
- **URL 경로**: `/gigs`
- **대상 사용자**: 모든 사용자. 공개 공연은 누구나 열람할 수 있고, 비공개 공연은 해당 공연 참여자와 관리자만 목록 및 상세를 열람할 수 있습니다.
- **목적**: 동아리의 예정된 공연과 지난 공연 아카이브를 탐색하고, 각 공연의 상세 정보 화면(`/gigs/[id]`)으로 이동. 로그인 회원에게는 선곡 회의 바로가기 제공, 관리자에게는 신규 공연 등록 진입점 제공.

## 3. 사용자 인터랙션 및 UX 흐름 (User Interactions)

1. **공연 카드 클릭 및 호버 효과**:
   - 다가오는 공연 또는 지난 공연 카드를 클릭하면 해당 **공연 상세 정보 화면(`app/gigs/[id]`)**으로 라우팅됩니다.
   - 마우스 호버 시 카드가 부드럽게 위로 살짝 떠오르는 트랜지션(`hover:-translate-y-1.5`)이 적용되며, **포스터 이미지는 확대되지 않고 안정적으로 유지**됩니다.
   - Supabase 공개 Storage 포스터는 카드 너비에 맞춰 최적화하고 화면의 첫 공연 포스터를 우선 로드합니다. 외부 이미지 URL은 직접 표시하며 나머지 포스터는 지연 로드합니다.
   - 지난 공연 역시 흐리게 처리(딤/그레이스케일)하지 않고 **100% 선명한 원본 컬러**로 유지되며, 공연일시 맨 앞에 `[종료]` 뱃지를 배치하여 상태를 구분합니다.
   - 공연 부제목은 **메인 제목 바로 다음 줄에 독립적으로 정돈되어 배치**됩니다.
   - 선곡 회의 관련 정보는 공연 목록 및 카드에서 노출되지 않습니다.
2. **관리자 공연 등록 액션**:
   - 관리자 계정으로 로그인한 경우에만 타이틀 우측에 `+ 공연 등록` 버튼이 노출됩니다.
   - 클릭 시 공연 등록 페이지(`/gigs/new`)로 이동합니다.

## 5. 백엔드 데이터 연동
- **조회 쿼리**:
  ```ts
  const { data: rows } = await supabase
    .from("gigs")
    .select("*")
    .order("perform_date", { ascending: false });
  ```
- **날짜 필터링 로직**:
  - `now` (오늘 00:00:00) 기준으로 `perform_date >= now`는 `upcomingGigs`, 미만은 `pastGigs`로 분류.
  - `upcomingGigs`는 날짜가 가까운 순서(오름차순)로 `.reverse()`하여 정렬.
