# 02. 공연 목록 페이지 (`/gigs`)

## 1. 개요 및 접근 권한
- **URL 경로**: `/gigs`
- **대상 사용자**: 모든 사용자 (방문자, 일반 회원, 관리자)
- **목적**: 동아리의 예정된 공연과 지난 공연 아카이브를 탐색하고, 각 공연의 선곡 회의(셋리스트) 화면으로 이동. 관리자에게는 신규 공연 등록 진입점 제공.

## 3. 사용자 인터랙션 및 UX 흐름 (User Interactions)

1. **공연 카드 클릭**:
   - 다가오는 공연 또는 지난 공연 카드를 클릭하면 해당 공연의 선곡 회의 화면(`app/gigs/[id]/setlists`)으로 즉시 라우팅됩니다.
   - 마우스 호버 시 카드가 살짝 위로 떠오르는 트랜지션 효과(`hover:translate-y-[-4px]`) 제공.
2. **관리자 공연 등록 액션**:
   - 관리자 계정으로 로그인한 경우에만 타이틀 우측에 `+ 공연 등록` 버튼이 노출됩니다.
   - 클릭 시 공연 등록 페이지(`/gigs/new`)로 이동합니다.

## 4. UI 상태 (States)

| 상태 | 화면 표시 및 처리 |
| :--- | :--- |
| **로딩 (Loading)** | `<Suspense fallback={<GigsFallback />}>`: `"불러오는 중…"` 문구 표시 |
| **예정 공연 없음 (Empty)** | 대시보드 형태의 점선 박스: `"준비 중인 공연이 없습니다."` |
| **지난 공연 없음 (Empty)** | 안내 텍스트: `"지난 공연 기록이 없습니다."` |
| **일반 회원/방문자** | `공연 등록` 버튼 숨김 처리 |
| **관리자 (Admin)** | `공연 등록` 버튼 노출 (`getIsAdmin()` 검증 완료 시) |

## 5. 백엔드 데이터 연동
- **조회 쿼리**:
  ```ts
  const { data: rows } = await supabase
    .from("gigs")
    .select("*")
    .order("perform_date", { ascending: false });
  ```
- **날짜 필터링 로직**:
  - `now` (오늘 00:00:00) 기준으로 `perform_date >= now`는 `upcomingGigs`, 미만은 `pastGigs`로 분류.
  - `upcomingGigs`는 날짜가 가까운 순서(오름차순)로 `.reverse()`하여 정렬.
